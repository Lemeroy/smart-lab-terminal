| 文档项 | 内容 |
| --- | --- |
| 文档编号 | SLT-PLAN-001 |
| 版本 | 0.1.0 |
| 编写日期 | 2026-10-12 |
| 状态 | 设计基线，尚未执行业务开发和真实场景验收 |
| 对应设计 | [智能实验室终端设计开发文档](智能实验室终端设计开发文档.md) |
| 适用对象 | 产品负责人、终端开发、视觉算法、后台开发、测试和实验室运维 |

**目标：**交付能够记录实验开始与结束状态、自动判断仪器位置变化及桌面扰乱度、支持教师只读查看和报告导出的终端系统。

**架构：**终端负责采集、图像质量检查、端侧分析、学生交互和断网缓存，本地完成会话，后台同步状态独立。后台保存版本化记录并提供教师只读查询，默认不重新计算；如启用服务端复算，必须创建新分析 attempt 并保留原结果。AnchorDiff 作为独立外部算法依赖接入，实验室业务、身份数据和现场图片保留在本仓库对应的私有部署中。

**建议技术栈：**Python、FastAPI、OpenCV、AnchorDiff、ONNX Runtime 或 RKNN Runtime、Vue/TypeScript、终端 SQLite、后台 PostgreSQL。版本需在各阶段以实际兼容结果锁定。

本计划规定交付顺序、接口门禁和验收证据。文中的工期、样本量、精度、延迟和容量均为建议规划或验收目标，不表示当前已经实现或验证；进入试点前必须用实际设备和现场数据确认。

## 1. 全局约束

1. 流程为：登录/选实验 → 首次拍照 → 记录仪器及位置 → 资料与清单 → 学生点击结束 → 收台向导 → 结束拍照 → 系统判定 → 教师只读查看 → 导出报告线下反馈。
2. 只对仪器做目标检测和位置记录。小器件、线缆和个人物品可以表现为残余变化，不要求逐件识别。
3. 标记只用于相机定位及图像对齐，不作为仪器身份标签。
4. 本次合格首拍是比较基线，不预设固定归位区，也不把限定 4–6 类仪器作为启动条件。
5. 默认位置容差为 `0.1`。归一化位移为中心点欧氏距离除以 `max(sqrt(before_bbox_area), sqrt(after_bbox_area), 1)`，不是桌面宽度的十分之一。
6. 扰乱度为相对基线的 `0–1` 分数，越高表示未恢复变化越多；不解释成学生成绩、事故概率、安全合格结论或绝对整洁等级。
7. 质量门控失败时返回 `disorder_score=null`、`needs_review=true` 和原因。学生可在首次终拍之外最多额外重拍 3 次，持续失败交由运维排查；教师只能查看，不能改分或改算法结论。
8. 同类目标匹配不等于确认物理资产身份；同类替换、遮挡及无法匹配情况必须保留不确定性。
9. 固定或基本固定的相机是前提。后上方斜视可试用，但平面单应性不能消除高仪器的视差，必须以实际安装高度、镜头稳定性和定位误差验收。
10. RK3588 是候选端侧平台，上板兼容性、速度、温度和长期稳定性尚需实测；模型训练在具有合适算力的开发主机进行。
11. AnchorDiff 公开库与本系统保持项目边界，不向其公开仓库加入实验室身份、课程、台位、现场数据或业务文档。
12. 本系统仓库保持私有，README 使用中文。GitHub 远端已设为私有；其他远端也须为私有仓库，仅授权成员访问。
13. 首版在首拍时冻结有效矩形 ROI，裁剪后的整幅分析输入即评分分母；同一会话各次 attempt 使用相同 ROI 和尺寸。结束图无法覆盖完整冻结 ROI 时拒答，禁止为了通过分析按 attempt 缩小 ROI。

本设计核实的 AnchorDiff 基线为 `v0.6.1`、commit `e5d6798`。接入时锁定完整提交哈希及依赖版本，不通过浮动分支自动升级。现有 `analyze_pair` 的规则分支未纳入熵项，权重和为 `0.95`；输出仍属于 `0–1` 域，但不把实际可达上限承诺为 `1`。后续纳入空间熵或重标定分数时必须更新 `rule_version` 并重新评估。

## 2. 分工与整体排期

建议按照下列顺序交付，每阶段以完成门禁而非日期自动通过。单人开发可串行执行；有多名开发者时，UI、后台和数据标注可在统一契约冻结后并行。

| 阶段 | 建议投入 | 前置条件 | 可审查交付物 | 通过门禁 |
| --- | --- | --- | --- | --- |
| P0 需求与契约冻结 | 3–5 个工作日 | 本设计文档 | 需求矩阵、状态机、结果 Schema、安装试测方案 | 流程、权限、分数含义和不确定结果一致 |
| P1 相机与算法集成样机 | 1–2 周 | P0；可用相机和开发主机 | 首末拍样本、对齐图、坐标契约、AnchorDiff 适配器 | 采集重复性和坐标正确性通过 |
| P2 无训练模型的业务闭环 | 1–2 周 | P0；P1 接口 | 终端 UI、会话持久化、教师只读页、报告 | 使用人工标注检测输入打通完整流程 |
| P3 仪器检测训练与离线评估 | 2–4 周，可与 P2 并行 | P1 稳定拍摄方案、数据规范 | 数据清单、训练记录、模型卡、冻结测试报告 | 数据不泄漏，检测和系统状态指标达标 |
| P4 端侧部署与真实闭环 | 1–2 周 | P1–P3；RK3588 候选板 | ONNX/RKNN 适配、实际硬件性能报告 | 解码一致性、端侧精度和热稳定性通过 |
| P5 异常、权限与运维验收 | 1–2 周 | P2、P4 | 故障注入报告、授权测试、备份恢复记录 | 断网断电可恢复、记录不篡改、导出安全 |
| P6 小范围现场试点 | 至少 2 个教学周期 | P5 | 独立场次数据、反馈、验收报告 | 实测证据充分，缺陷闭环后再扩展 |

产品负责人维护需求和范围；视觉开发负责质量、检测、几何、匹配、评分和模型版本；终端开发负责采集与会话状态；后台开发负责认证、只读权限、同步和报告；测试负责冻结数据、故障注入和验收证据；运维负责镜头、灯光、网络、存储和设备更换。人员可以兼任，但测试集和验收结论必须保留独立审核记录。

## 3. 建议工程结构与接口归属

以下是开发阶段的建议结构，目前不表示目录或业务实现已经存在。

```text
apps/
  terminal-ui/                 学生触摸屏界面
  teacher-web/                 教师只读后台
services/
  terminal/
    sessions.py                会话状态机和结束幂等控制
    capture.py                 相机采集、质量选帧和曝光设置
    alignment.py               标记几何定位及基线坐标转换
    analysis_adapter.py        AnchorDiff 输入输出转换
    local_store.py             本地事务和离线队列
    sync.py                    后台同步及冲突处理
  server/
    auth.py                    认证和权限执行
    records.py                 会话与分析记录只读查询
    exports.py                 脱敏报告和导出审计
    retention.py               数据留存及清理
contracts/
  session.schema.json          会话与状态事件契约
  analysis.schema.json         算法结果与证据契约
  openapi.yaml                 API、权限和错误码
vision/
  detectors/                  模型解码、NMS、坐标逆变换
  evaluation/                 训练和系统评估脚本
configs/
  analysis.example.yaml       无敏感值的配置示例
  capture.example.yaml        无设备密钥的相机配置示例
tests/
  contracts/ integration/ e2e/ hardware/
deploy/
  terminal/ server/           服务启动、备份和恢复说明
docs/
  模型训练与部署规范.md
  验收报告模板.md
```

关键接口在 P0 冻结字段和单位，在 P1 冻结具体类型。建议接口为：

```text
capture_candidates(session_id, stage) -> 帧候选及各自质量元数据
select_frame(candidates) -> selected_frame_id 或 quality_failure
align_to_baseline(baseline_image, selected_image, anchors, frozen_roi) ->
    aligned_image, geometry_evidence, frozen_roi_coverage
detect(aligned_image) -> label, bbox_xywh, confidence, optional_mask
analyze(baseline_image, aligned_image, baseline_detections, final_detections,
        config_snapshot) -> immutable_analysis_result
persist_result(session_id, revision, result, artifact_manifest) -> result_id
sync_record(record_id, idempotency_key) -> acknowledged 或 retryable_failure
```

检测框为分析图坐标系中的 `x,y,width,height`，mask 大小与分析图一致；图像和标签必须携带 `image_id`、`coordinate_space_id`、宽高以及转换版本。未通过质量或几何门禁时停止后续判定，不制造空检测后再推导“全部缺失”。

正式会话 lifecycle 使用下列枚举，不与同步状态混用：

| 状态 | 含义与正常出口 |
| --- | --- |
| `AWAITING_BASELINE` | 等待合格首拍；成功进入 `IN_PROGRESS` |
| `IN_PROGRESS` | 学生进行实验；点击结束进入 `CLEANUP` |
| `CLEANUP` | 收台向导；确认后进入 `AWAITING_FINAL`，正常流程不得返回实验进行状态 |
| `AWAITING_FINAL` | 等待结束采集；成功进入 `ANALYZING` |
| `ANALYZING` | 端侧执行当前 attempt；可靠结果进入 `FINALIZED`，质量失败进入 `RECAPTURE_REQUIRED` |
| `RECAPTURE_REQUIRED` | 引导学生额外重拍；有余量时进入 `AWAITING_FINAL`，额外重拍 3 次仍失败进入 `INCOMPLETE` |
| `FINALIZED` | 已有不可覆盖的可靠结果；后台同步单独进行 |
| `INCOMPLETE` | 收台结束但无法可靠判定或证据不完整；保留空分数、原因和已产生的 attempts |
| `CANCELLED` | 尚未进入 `IN_PROGRESS` 时受控取消，留最小审计；实验开始后异常关闭进入 `INCOMPLETE` |

额外重拍上限为 3 次，即最多 1 次首次终拍加 3 次额外终拍。已完成会话的常规学生界面不能重开实验；可选服务端复算只能生成新 attempt，不能覆写已存在结果。取消及系统异常必须记录理由，不能用取消绕过正常收台流程。

## 4. 分阶段工作包

### P0：需求、契约与试测基线

**输入：**主设计文档、现场桌面尺寸、仪器种类、候选相机和网络条件。

**交付文件：**`contracts/session.schema.json`、`contracts/analysis.schema.json`、`contracts/openapi.yaml`、`docs/验收报告模板.md`，以及文档中的需求追踪更新。

- [ ] 明确学生登录方式、终端与台位绑定方式、课程清单来源和留存策略。身份方案仅收集必要标识，不将姓名写进文件名、日志或图像。
- [ ] 冻结本计划定义的正式 lifecycle 和合法转换，禁止直接从登录状态跳到判定完成；结束请求重复发送必须返回原有收台步骤或已有结果，进入正常收台流程后不得返回 `IN_PROGRESS`。
- [ ] 将业务状态、分析 attempt 状态和同步状态分别定义。会话本地完成与网络同步成功不互为前提；每次重拍创建新 attempt，保留前次失败原因和图像关联。
- [ ] 给每个结果记录模型、算法、配置、相机标定和输入图像哈希；对模型、阈值更新采用新版本，历史记录保留当时版本。
- [ ] 定义 `needs_review` 的可见文案：“本次无法可靠分析，请重拍或联系运维”，并保留机器可读原因码。
- [ ] 冻结报告字段：会话伪名、实验名称、首末拍时间、仪器位置状态、bbox 说明、残余区域、分数/不可判定原因、版本和记录 ID。
- [ ] 编制相机位置 A/B 试测表。至少比较高位近顶视与后上方斜视，记录覆盖、遮挡、高物体视差、触摸屏反光、日常碰撞和安装维护成本。

**完成定义：**每项需求都有唯一 ID、实现任务、验收证据；结果 Schema 能表达稳定、移位、缺失、新增、不可判定和残余变化；没有教师改分或改判 API。

### P1：采集、坐标与 AnchorDiff 集成

**依赖：**P0；版本锁定的 AnchorDiff；一台普通开发主机和候选相机。先验证准确性再决定端侧采购规模。

**交付文件：**`services/terminal/capture.py`、`alignment.py`、`analysis_adapter.py`、`tests/integration/test_geometry_contract.py`、`docs/相机安装与标定记录.md`。

- [ ] 采集稳定桌面重复图像，比较自动曝光与锁定曝光；在持续亮度变化时记录门控行为，避免把照明变化直接判为扰乱。
- [ ] 把首次合格帧和结束选中帧分别固定下来，所有检测必须对应准确的帧 ID。多帧场景先选帧再检测，不对全部帧复用同一组框。
- [ ] 将结束图像先对齐到基线图坐标，再在对齐图上检测，保证 AnchorDiff 输入检测框和图像同坐标。不要依赖尚未同步变换 final 检测框的路径。
- [ ] 首拍冻结有效矩形 ROI，并以此裁剪首末分析输入。AnchorDiff v0.6.1 的现有分母是整个输入图，不能把任意 valid ROI mask 当作已支持能力；结束图无法完整覆盖冻结 ROI 时直接拒答。
- [ ] 外部对齐在调用 core 前执行独立门控，并将几何证据与原因保存进 attempt。core 对预对齐输入产生的恒等对齐 `confidence=1` 不得覆盖或抬高外部对齐置信度，也不得解除此前失败状态。
- [ ] 使用一组已知角点和人工框验收透视变换、ROI、letterbox 逆变换和 bbox/mask 尺寸。设置非方形输入测试，捕获宽高顺序错误。
- [ ] 在对齐图上输出 overlay；如展示原始结束图，则显式对 bbox 和 mask 做逆变换。绝不在原图上直接叠加分析坐标 mask。
- [ ] 测试默认容差 `0.1` 附近的合成位移，以及实际不同大小仪器的中心定位重复性；合成测试只验逻辑，不代替真实精度。
- [ ] 记录稳定小位移的边缘残余现象，设计边缘带容忍策略的对照实验；不能简单清空整个稳定 bbox 内的变化，以免掩盖真实残留物。
- [ ] 增加缺标记、手部/遮挡、强相机位移、检测异常为空等应用层门禁，说明哪些由可计算规则判断、哪些只能提示重拍。

**完成定义：**同一坐标系契约全部通过；标记失效不产生自信分数；基线冻结后不因重试而静默换图；能够输出可追溯的算法结果与 bbox/残余说明。未通过这些门禁不得进入真实仪器结果演示。

### P2：先完成业务闭环

**依赖：**P0 API 和 P1 图像契约。允许使用已明确标记为人工标注输入的检测数据进行开发，以免业务进度依赖模型训练完成。

**交付文件：**`apps/terminal-ui/`、`apps/teacher-web/`、`services/terminal/sessions.py`、`local_store.py`、`services/server/records.py`、`exports.py` 和端到端测试。

- [ ] 实现登录、实验选择、首拍倒计时、资料与清单、点击结束、收台步骤、终拍、结果解释与重拍路径。
- [ ] 首拍质量未通过时不能进入正常实验状态；首拍已通过后持久化，不因应用重启自动重建。
- [ ] 收台向导按本次基线显示仪器和提示，位置大体恢复即可；不得生成固定归位区要求。
- [ ] 保存状态转移、采集事件和结果，使用事务把“分析完成”和本地记录写入一起提交。失败后保持可重试状态。
- [ ] 后台只读查询详情、时间筛选、台位/课程筛选和报告导出；任何写分、改状态、替换原始证据的请求均由服务端拒绝。
- [ ] 教师详情页同时显示扰乱度、每个对象 bbox 对应变化及残余区域。分数为空时显示原因，不能显示 `0` 或默认“整洁”；学生端只显示提交、重拍、不可判定和同步状态，不展示完整分数与逐框报告。
- [ ] 首次终拍之外最多允许 3 次额外重拍，持续失败后以 `INCOMPLETE` 保存“不可判定”收台记录并提示运维处理，避免学生陷入循环；允许重拍的状态下，每次学生触发采集创建独立 attempt，不覆盖此前结果。
- [ ] 将技术错误隐藏在学生正常流程之外，学生看到可行动提示；运维页和日志保留原因码、设备状态和记录 ID。

**完成定义：**使用人工检测输入可以从登录走完报告导出；重复结束不重复建会话；教师只读在后端执行；所有截图、日志和导出均通过去敏审查。

### P3：数据集与仪器检测训练

**依赖：**P1 安装方案；数据规范。类别数由实际教学需要和可获得训练数据决定，新类别必须有数据及验收记录。

**交付文件：**`vision/evaluation/`、数据 manifest、标注规范、训练配置、模型卡、冻结测试报告；真实图像和权重存放在 Git 外受控位置。

- [ ] 按台位、日期、采集场次和物理仪器实例建立分组清单。相邻帧、同一桌面布置及高度近似的首末图不能随机拆到训练和测试两侧。
- [ ] 记录仪器类别、完整 bbox、遮挡程度和可见性。加入无目标图、相似物品、多台同类仪器及大幅光照差异，不把线缆硬编为仪器类别。
- [ ] 先完成可复现的轻量检测基线，按真实数据比较 nano/small 模型的精度、漏检率、定位重复性和端侧时延；不从参数量直接宣称更适合。
- [ ] 只用训练集调模型、验证集选超参数，冻结测试集一次性评估。任何查看测试错误后进行针对性修改，都必须记录并重新建立独立测试集。
- [ ] 把同类仪器调换、明显离位、部分遮挡、仪器缺失、新增仪器和纯桌面残余变化作为独立系统样本，不只报告检测 mAP。
- [ ] 验证高成本候选拒配、unmatched 处理和同类身份不确定性；仅同类别几何匹配不足以证明原仪器未被替换。
- [ ] 记录模型许可证、训练框架版本、数据授权、训练 seed、split manifest 哈希和权重哈希。使用模型代码与权重前分别核对许可证。

**完成定义：**训练可重跑，测试分组可核查，指标按类别和场景报告；系统缺失误报、位置状态及质量拒答通过建议门槛或有明确降级方案。

### P4：RK3588 部署与真实性能

**依赖：**P3 选定模型；P1 坐标契约；RK3588 候选板和与生产相同的供电、散热、相机。

**交付文件：**`vision/detectors/`、端侧依赖锁定、模型转换配置、`tests/hardware/` 和硬件评测报告。

- [ ] 导出 ONNX，针对实际模型原始输出实现解码、置信度计算、NMS 和 letterbox 逆变换。AnchorDiff 的默认六列输出解码不能直接视为任意 YOLO 头部解码。
- [ ] 通过同一批图对照训练框架与 ONNX 的类别、坐标、分数和 NMS 结果。非方形输入、RGB/BGR、NCHW/NHWC 均单独验收。
- [ ] 按实际 RKNN Toolkit/Runtime 版本转换并核对 Runtime API 类名和输入布局；禁止以桌面 ONNX 通过代替 RKNN 已兼容。
- [ ] INT8 校准只使用训练或单独校准集，覆盖实际曝光和仪器尺度；与 FP32/FP16 比较关键指标下降，不使用冻结测试集做量化调参。
- [ ] 测量单次采集到结果显示的总时延和各步骤耗时；同时记录 p50、p95、峰值内存、CPU/NPU 利用率、温度及频率。
- [ ] 连续运行至少 8 小时进行热稳定试测，模拟高温季节条件并采用设备允许的范围；发生降频、USB 摄像头重连和内存增长时暂停采购扩展。

**完成定义：**真实硬件链路无坐标偏差，精度损失可接受，延迟和长时间稳定性有可复查记录。若 NPU 适配未通过，使用已验证的 CPU/ONNX 方案继续试点，并明确性能限制。

## 5. AnchorDiff 接入门禁

| 门禁 | 当前风险 | 实现要求 | 验收证据 |
| --- | --- | --- | --- |
| INT-01 统一坐标 | 图像对齐后，final bbox/mask 可能仍为原坐标 | 先对齐再检测；把坐标空间 ID 放入契约 | 已知透视角点及 bbox/mask 对照图 |
| INT-02 正确选帧 | 多帧共用检测结果导致错配 | 选帧完成后只检测所选帧 | 帧 ID 与检测、overlay 一一一致 |
| INT-03 可视化一致 | 原图叠加分析 mask 会偏位 | 对齐图上渲染或显式反变换 | 至少一个非恒等变换用例 |
| INT-04 模型输出适配 | YOLO raw head 非默认六列输出 | 模型专用解码、NMS、letterbox 逆变换 | 框坐标与框架参考结果比较 |
| INT-05 NPU 接口 | Toolkit/Runtime API 与输入布局可能不同 | 锁定实测版本并检查 Runtime 类名、通道、布局 | 板上加载和固定样本结果 |
| INT-06 非方形输入 | resize 宽高约定易混淆 | 统一 `(width,height)`/张量约定 | 非方形输入坐标恢复测试 |
| INT-07 质量门控 | 原库不覆盖完整手部遮挡、缺标记及空检测 | 应用门控失败输出空分数和原因 | 异常照片不能获得自信结论 |
| INT-08 高成本拒配 | 同 label 匈牙利可能强行匹配不相关目标 | 明确拒配条件和 unmatched，不报告资产身份 | 同类替换、大跨度移位测试 |
| INT-09 小位移残余 | 稳定对象仍可能产生边缘差分 | 记录局限并比较边缘带策略，不掩盖框内杂物 | 小位移与新增残留对照 |
| INT-10 固定 ROI 与分母 | core v0.6.1 用整幅输入作为分母，不支持任意 valid ROI mask | 首拍冻结矩形 ROI 和尺寸；所有 attempt 使用同一裁剪，覆盖不足拒答 | 边界缺失、ROI 不可完整覆盖、重拍分母不变测试 |
| INT-11 外部对齐质量 | core 恒等对齐 confidence=1 可能掩盖外部变换失败 | core 前独立门控，外部质量证据不可被 core 结果覆盖 | 外部低置信度与 core 恒等对齐并存时 score=null |

门禁失败必须阻止相应功能进入正式验收。可以展示算法研究结果，但页面和报告应明确“测试模式”，不能把未通过链路提供给正常教学使用。

## 6. 建议验收指标与数据要求

### 6.1 建议门槛

以下指标为候选门槛。P0 应确认使用环境和可接受误报成本；之后不能为了通过验收而在查看冻结测试结果后降低门槛。

| 指标 | 建议门槛/口径 | 验收条件与限制 |
| --- | --- | --- |
| 流程正确性 | 核心流程和异常分支用例 100% 通过 | 自动化与人工触摸屏操作共同验证 |
| 未授权写结果 | 所有教师/学生写分、改判请求被拒绝 | 检查 API、批量接口、导出及跨会话访问 |
| 仪器检测 | 各主要类别 Precision ≥ 0.90、Recall ≥ 0.90；增强目标均 ≥ 0.95 | 以 IoU ≥ 0.50 计算，置信度在验证集冻结；分别报告无遮挡/轻遮挡及样本数、区间 |
| 原位重复性 | 原位重复拍摄中归一化位移 p95 ≤ 0.05 | 为 `0.1` 容差留定位噪声余量；各仪器尺寸分层 |
| 位置状态 | stable/moved/missing/new 宏平均 F1 ≥ 0.90 | 对 `0.1` 附近样本单独统计；资产身份不纳入 |
| “缺失”误报 | 在实际存在且可见的仪器中误判 missing 比例 ≤ 0.03 | 严重遮挡应拒答，单独报告拒答覆盖率 |
| 稳定误报移动 | 参考状态为 stable 的实例中误判 moved 比例 ≤ 0.05 | 报告目标尺度、安装视角及阈值边界分层 |
| 正常覆盖率 | 预先参考定义为正常的输入获得可靠非空分数的比例 ≥ 0.90 | 分母为预先定义的正常验收样本，不以排除错误样本提高覆盖 |
| 严重质量拒答 | 严重缺标记、运动、遮挡、过曝样本的拒答召回 ≥ 0.95 | 同时报告正常覆盖率，不能通过全部拒答获取高可靠性；一旦已标记门控失败必须 score=null |
| 扰乱度 | 同类合成扰动强度增加时分数顺序正确；真实场景排序与独立参考排序比较 | 不强行解释为概率；真实参考有分歧时记录分歧 |
| 残余解释 | 计算 residual mask/region 与人工变化区域的 IoU 或定位召回 | 区分高物体视差、光照和实际残留，不用 bbox 面积替代分割准确率 |
| 用户可见时延 | 从确认终拍到显示结果 p95 ≤ 5 秒，至少 200 次有效测量 | 在实际板卡、分辨率和仪器数量下测量；拍摄倒计时另计，失败次数另报 |
| 离线缓存 | 至少容纳 1 个教学日的会话与证据 | 按实测图片大小计算磁盘需求；存满有明确阻断提示 |
| 同步可靠性 | 重复投递、断点上传不重复建记录；哈希一致 | 断网、超时、后台重启和权限过期故障注入 |
| 稳定运行 | 8 小时连续试测无崩溃、持续内存增长或不可恢复失联 | 记录温度、降频和每小时性能，不仅记录进程存活 |
| 数据留存 | 清理遵循配置且不删除未同步/未完成记录 | 包括备份、缓存、临时图和导出目录 |

### 6.2 验收数据构成

1. **坐标契约数据：**带已知变换的图像、非方形输入、不同 bbox 尺寸、对应 mask，以及至少一个非恒等单应性。用于排查几何错误，不计为现场精度。
2. **检测冻结集：**按采集场次、台位和物理仪器实例分组；主要类别建议先获得至少 100 个独立可见实例，再根据区间宽度追加。100 个实例不代表已经充分覆盖教学场景。
3. **状态成对集：**建议至少 200 组独立首末拍，覆盖稳定、小幅移动、明显移动、缺失、新增、同类替换、纯残余变化和多目标。相邻帧不作为独立样本扩大数量。
4. **阈值边界集：**对每种代表性目标采集位移位于 `0.08–0.12` 的样本，同时覆盖不同框尺寸；记录人工中心标注误差，不能把标签噪声归因于算法误报。
5. **质量与安装集：**遮挡、无标记/部分标记、相机碰动、反光、过曝、弱光、桌面外变化、高仪器视差和无目标场景。
6. **系统故障集：**断电模拟、进程异常退出、断网、后台超时、磁盘不足、图片损坏、模型缺失、配置不兼容和时钟偏差。

比率同时报告分子、分母和 Wilson 95% 置信区间。对于零次缺失误报，使用单侧 95% 二项上界时，约 100 个独立样本可将上界压到约 3%，约 300 个可压到约 1%；这只是样本量规划依据，不替代实际分层评估。台位/场次内样本相关时应按场次统计或分组 bootstrap，不能当作完全独立。

扰乱度使用预先定义的成对排序或人工区域标注验证；多位参考标注者先记录一致性。报告拒答率、非拒答结果的错误率及二者关系，明确系统牺牲多少覆盖率换取可靠性。

## 8. 故障恢复验收矩阵

| 故障时点/类型 | 期望行为 | 禁止行为 |
| --- | --- | --- |
| 首拍尚未通过时退出 | 恢复到待首拍，提示重新采集 | 自动生成空基线 |
| 首拍已冻结后退出 | 恢复原会话、基线和实验资料 | 静默换基线或丢失会话 |
| 收台向导中退出 | 恢复向导或再次确认结束 | 无终拍直接判定完成 |
| 终拍完成但分析中断 | 保留选中帧和任务 ID，幂等重试 | 换一张结束图却复用旧检测 |
| 分析完成但后台不可达 | 学生端显示完成/待同步状态并排队同步，完整结果本地保存 | 丢失结果、泄露完整分数或要求教师手工补分 |
| 允许状态内重拍/可选后台复算 | 创建新 attempt，保留输入和版本；正常流程选首个有效结果，复算按系统规则追加选定事件 | 更新原 attempt、重开正常实验或在后台静默替换分数 |
| 重复结束/重复同步 | 返回原结果或同一修订的状态 | 重复会话、重复报告或多份同版本结论 |
| 上传部分成功 | 标注证据未完成，重试缺失内容 | 后台声称证据完整 |
| 图片损坏/模型缺失 | 不可判定并保留原因，运维修复 | 默认分数为 0 |
| 磁盘不足 | 在保证可持久化前阻断新会话，提示运维 | 删除未同步证据或继续无记录实验 |
| 新模型/配置不兼容 | 拒绝启动该分析版本并回退已验证版本 | 混用新模型与旧解码 |
| 终端时钟偏差 | 记录终端与服务端时间，保持会话事件顺序 | 静默伪造采集时间 |
| 相机移位/标记不可用 | 学生重拍；持续失败进入运维处理 | 将全部仪器误判移位且输出确定分数 |
| 额外重拍 3 次仍失败 | 进入 `INCOMPLETE`，score=null 并保留所有 attempt | 再次自动重拍或重开 `IN_PROGRESS` |
| 结束图无法覆盖冻结 ROI | 拒答并保留外部几何原因 | 缩小 ROI、改变分母或用 core confidence=1 消除失败 |

每类故障至少在一次真实终端环境中演练；会话数据库状态、outbox、图像 manifest 和后台结果应共同检查。出现结果冲突时保留原始记录、阻止覆盖，并生成运维事件。

## 9. 采购实测门槛

不得仅根据“有 NPU”或摄像头像素数量冻结采购。第一轮购买以 1 套候选设备验证，后续数量以 P4/P6 证据决定。

| 项目 | 试测内容 | 冻结采购条件 |
| --- | --- | --- |
| 相机/镜头 | 桌面覆盖、最小目标像素、曝光锁定、USB/CSI 支持、反光与畸变 | 主要仪器无遮挡，首末拍重复性和检测达到门槛 |
| 安装支架 | 高位近顶视与后上方斜视 A/B、碰撞后变化、镜头维护 | 采用满足场景精度且可长期固定的安装方案 |
| 定位标记 | 视野内数量、遮挡、打印平整度、固定方式 | 常态可见，缺失时能可靠拒答；不用于仪器身份 |
| 补光 | 漫射、反光、阴影、闪烁和曝光波动 | 正常课程时段不会引入持续虚假残余 |
| RK3588 板卡 | OS、摄像头驱动、RKNN 版本、RAM、存储、USB 带宽 | 模型实际加载、端侧链路与 8 小时稳定性通过 |
| 散热/电源 | 峰值负载、外壳、温度、掉电/重启 | 无供电不足、持续降频或不可恢复摄像头掉线 |
| 触摸屏 | 字体与手指点击、误触、分辨率、亮度、耐清洁 | 学生独立完成流程；实验器材不会遮挡重要按钮 |
| 存储 | 实际单会话大小、写入速度、保留期、恢复 | 一个教学日离线余量和安全清理通过 |

若斜视安装造成高仪器视差导致误报，优先调整相机位置、镜头高度和重复定位，随后才评估局部对齐或多视角成本。不得用增大阈值掩盖未验证的几何误差。

## 10. 发布、维护与记录

开发者完成一个工作包后应提交代码、必要测试和对应文档。CI 执行契约验证、算法适配回归、权限测试、依赖检查和提交内容去敏审查；真实身份、原始图片、模型权重和设备密钥不得进入提交。远端及仓库协作权限应符合私有项目要求。

建议每个工作包完成时运行以下定向验证。命令用于未来已建立开发环境和测试文件的实现仓库，当前文档阶段不能把它们的存在或通过情况视为已完成。Windows 无需激活环境即可调用虚拟环境中的解释器。

```powershell
# P0：结果与会话契约，包括 score=null 与 bbox 坐标字段
.\.venv\Scripts\python.exe -m pytest tests/contracts -q

# P1：已知透视变换、选帧、非方形输入、框和 mask 的坐标契约
.\.venv\Scripts\python.exe -m pytest tests/integration/test_geometry_contract.py -q

# P2/P5：完整流程、权限、幂等同步、重启恢复和导出
.\.venv\Scripts\python.exe -m pytest tests/e2e -q

# P4：必须在候选端侧设备上运行相应 hardware 测试并保存环境记录
# Linux 板卡中使用 .venv/bin/python -m pytest tests/hardware -q
```

通过要求是退出码为 `0`，必要硬件用例全部执行且无跳过；存在失败时暂停对应门禁。检测精度、量化损失、延迟和热稳定性须另附真实数据报告，不能以单元测试通过代替。

每次发布至少记录：系统版本、AnchorDiff 版本、模型及解码器版本、配置版本、设备运行环境、迁移和回滚步骤、验证数据版本、测试结论及已知限制。现场发布先在一台终端验证，确认新会话正常、旧记录可读后逐步扩展。

| 维护周期 | 操作 | 记录 |
| --- | --- | --- |
| 每日/课前 | 检查相机画面、标记、存储余量和同步状态 | 台位健康状态与异常记录 |
| 每周 | 分析拒答原因、重拍次数、同步积压和设备温度 | 场景分类趋势，避免只看平均分 |
| 每月或硬件调整后 | 标定复核、固定样本回归、备份恢复抽查 | 标定版本、实测差异与恢复结论 |
| 每次模型更新 | 独立评估、量化对照、解码和端侧回归 | 模型卡、哈希、前后指标及回滚条件 |
| 每次数据导出/删除 | 校验权限、记录范围、执行留存策略 | 导出/删除审计，无明文凭据 |

## 11. 开发开始前需收集的信息

这些信息作为 P0 的现场调查交付物，不阻碍当前设计文档完成：实验桌尺寸与安装限制、实际仪器清单及外观差异、学生登录渠道、内网可达性、每日会话数量、报告格式要求、数据留存周期、预算区间以及可用训练主机。

在这些信息明确前采用可更换相机、参数化类别、版本化配置和单台位试点。未实测的型号、速度或精度不得写成产品承诺；未通过验收的功能保持开发或测试状态。
