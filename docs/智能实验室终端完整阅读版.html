智能实验室终端设计开发文档

本文定义智能实验室终端的产品行为、硬件方案、算法集成、软件架构、数据与安全规则，以及从原型到试点的开发方法。开发人员可以据此拆分任务，教师和实验室管理人员可以据此检查流程与验收范围。

系统以每次实验的首次有效桌面照片为基线，在收台后自动比较仪器位置和桌面可见变化，输出扰乱度、每个目标框的解释和证据记录。触摸屏提供实验资料与收台流程，教师后台查看记录和导出报告。

2 产品定义与边界

2.1 目标

终端减少实验前后记录和收台反馈的重复工作，并让每一项系统结论都能找到对应图像、目标框、位移或残余区域。系统不要求学生提前配置区域，也不要求管理员先把所有仪器分配到固定归位区。

首拍位置就是本次比较的期望位置。若首拍时已有杂物或仪器位置不符合实验室规范，这些问题可能不会作为新增变化出现。因此本系统输出的是相对基线的可见变化，不能单独证明桌面达到了统一卫生标准。

2.2 视觉对象

仪器检测类别按实际实验室需求建立，例如示波器、焊台、直流电源、万用表、信号发生器。类别数量可扩展，不把限定为 4–6 类作为实施前提。能否加入某类取决于镜头中是否可见、训练数据是否覆盖、定位框是否稳定以及独立测试是否通过。

电阻、电容、焊锡丝、线缆、纸张、个人物品等默认不逐项识别；其变化可能出现在残余区域中。解释应写“未被仪器变化解释的可见区域”，不能凭残余框认定其中一定是线缆、垃圾或私人物品。

检测类别不等于物理资产身份。两台同型号示波器交换位置，当前类别与几何匹配可能无法识别交换。需要资产追踪时，应另立需求并选择资产标签或专门身份识别，不把定位标记转用为仪器身份。

2.3 判定规则

系统自动输出对象变化与 disorder_score。教师后台只读查看及导出，不设置改分、改状态、人工覆盖或“复核通过”按钮。needs_review 在本系统界面表示“证据不足，系统暂不可判定”；教师可以查看这条记录，但不能通过填入分数解除状态。

扰乱度是规则生成的比较分，范围为 0–1，数值越高代表被计入规则的变化越多。它不等于风险概率、实验完成质量、仪器资产丢失、学生成绩或安全合格结论。焊台余温、电源断电和电气安全按实验规程处理，不能由桌面照片保证。

5 业务流程与异常处理

5.1 正常流程

学生先登录和选实验，系统检查相机、磁盘、当前会话及缓存资料。首拍前提示手和身体离开桌面视野，固定曝光后短时连拍，从质量合格帧中选择一帧，完成定位和检测后冻结有效基线。

实验中触摸屏显示资料与清单。学生点击“结束实验”后进入收台向导，依次确认停止操作、依实验规程处理供电与热源、收回个人物品、整理线缆、恢复仪器位置和退出拍摄区域。向导中的人工确认是操作记录，不是图像证明已经安全断电。

完成向导后终拍、挑帧、对齐、检测和分析。终端反馈提交完成、是否需要重拍与是否待同步；正常流程不向学生展示教师报告中的逐框分析和完整分数。教师查看系统保存的结果并导出，用于线下反馈。

5.2 状态与恢复

状态进入条件下一步与恢复规则
AWAITING_BASELINE授权登录后创建会话，等待有效首拍无效可重拍；没有有效基线不能进入正常分析
IN_PROGRESS有效基线与首拍检测已冻结查看资料与实验；重启恢复当前会话
CLEANUP点击结束进入向导；正常学生流程不提供返回实验入口
AWAITING_FINAL向导完成或系统要求重拍终拍；选中帧才进入分析
ANALYZING输入、版本与任务 ID 已持久化worker 计算；崩溃按同任务重试，避免重复结果
RECAPTURE_REQUIRED证据不可判定且仍有重拍预算按具体原因重拍；不输出有效分数
FINALIZED系统生成有效结果本地终结；后台显示结果只读；同步可仍 pending_sync
INCOMPLETE无有效基线、重拍耗尽或受控中断保存已有证据与原因；不能补造正常结果
CANCELLED尚未进入实验即取消会话留最小审计信息，不形成评分

业务状态、计算任务状态、算法可判定性和同步状态独立。FINALIZED + pending_sync 表示本地分析成功但尚未同步，不应显示“算法需复核”。建议终拍后最多 3 次额外重拍，次数属于版本化交互配置；超限保存不可判定记录并进入 INCOMPLETE，不强行生成分数。设备故障先恢复最后可靠状态，确实无法恢复时记录中断。

每次分析都是不可变 attempt。正常流程由系统选定首个通过全部门控的有效 attempt，学生不能比较分数后选择低分。重拍或运维重算新建记录并保留原因与旧引用，不能覆盖历史；提交后不能通过更换首拍基线消除已有变化。

6.2 后台与报告

列表分别显示分数、是否不可判定及同步/处理状态；不保留 level=clean/mild 等旧分类。详情页展示首拍、终拍、对齐图、逐框叠加图、对象变化表、残余区域表、质量原因和版本。原图和对齐图不能用同一坐标框混画。

对象说明举例：“示波器框中心移动 8 像素，对象尺度为 100 像素，归一化位移 0.08，小于容差 0.10，位置大体不变。”未检出写“结束图中未检出原有类别实例”，避免写“仪器遗失”。残余说明写“该区域有 420 个未解释变化像素，占有效桌面区域 0.12%”，不能写未检测到的具体物品名称。

报告包含会话代号、课程与工位、起止时间、首末拍时间、有效证据图、系统分数或不可判定原因、对象状态与位移、残余区域、配置/模型/算法版本和分析 attempt。默认使用学员代号；显示姓名须有明确课程授权。可附独立线下反馈页，但不在系统中写入教师改判定结果。

7.2 端侧与服务端职责

端侧受管视觉 worker 持有模型与冻结配置，完成分析并写入本地证据。触屏浏览器只能请求操作，不能指定分数、算法版本或上传任意正式结果。服务端按设备身份、工位归属、对象授权、schema、版本与内容哈希验证上传并归档。

设备认证证明来源及传输完整性，不能证明被攻陷设备的分析一定诚实。对高要求场景可增加签名软件、设备加固和独立服务端复算；复算生成带后端标识的新 attempt，不假设 RKNN 与 ONNX 结果逐数值相同。

8.2 安装位置比较

位置优点主要限制建议

单应性只保证近似共面桌面锚点的对应。示波器、焊台上部离桌面较高，相机移动后即使桌面锚点重投影误差很小，仪器仍可能出现假位移。因此要先稳定支架和视角，强运动时拒答，不把平面透视校正当成三维重建。

8.3 标定与安装验收

测量桌面可用范围、最高仪器和支架空间，使用厂家 FOV 数据估算镜头。近顶视时覆盖宽度约为 2 × 高度 × tan(水平视场角/2)；斜视不能直接套用该式决定覆盖范围，应现场检查最远端与遮挡。

先去镜头畸变，再用分散在桌面边缘、至少四个非共线且匹配可靠的锚点建立桌面坐标。标记 ID 对应锚点位置，尺寸由镜头中可辨识的像素数决定，不固定指定一种打印尺寸。相机、镜头、分辨率、支架或 ROI 改变时重新标定。

安装验收拍摄常用仪器布置、有人操作但尚未提交、收台无遮挡、最亮与最暗照明条件。记录桌面覆盖、定位稳定性、高仪器框抖动、反光和长时间温漂。若遮挡不可接受，调整支架或增加辅助相机需单独评审；首版不直接引入多视角融合增加复杂度。

容量示例：每会话保存 4 张平均 0.6 MB 的图，40 会话/日、30 天，约 2.9 GB 图像数据；还须加短时候选帧、失败 attempt、报告、数据库、模型和安全余量。该计算是规划示例，实际容量按试采集文件分布重新测量。

9 算法方案与 AnchorDiff 集成

9.1 完整链路

拍摄短序列 → 检查候选帧 → 选择最终帧 → 去畸变与桌面 ROI → 检查锚点和相机变化 → 对齐到冻结基线 → 在同一坐标图像上检测仪器 → 同类别匹配 → 解释仪器变化区域 → 计算残余差分 → 质量门控 → 生成数值与逐框证据。

基线的清晰度与锚点同样必须通过检查。终拍不能与任意旧实验或空桌模板比较。挑帧后再检测所选帧，不能复用另一帧的检测框。

9.3 位置容差

首末框为 b0=(x0,y0,w0,h0) 与 b1=(x1,y1,w1,h1)，框中心分别为 c0 与 c1。

scale = max(sqrt(w0*h0), sqrt(w1*h1), 1)
displacement = EuclideanDistance(c0, c1) / scale
stable  当 displacement <= 0.1
moved   当 displacement > 0.1

例如两次框均为 100×100 像素，中心移动 8 像素，归一化位移为 0.08；中心移动 12 像素则为 0.12。0.1 是相对目标尺度的位移，不是 0.1 像素，也不是桌面宽度的 10%。

框尺寸随视角、遮挡或检测抖动变化会影响归一化尺度。首版保留算法定义，并评估同一仪器重复拍照的框抖动；如未来改用固定基线尺度、底面点或实际毫米，必须新建配置/方法版本并重新做边界验收。

9.4 对象变化解释

同 label 目标通过几何代价矩阵与匈牙利算法匹配，输出 stable、moved、missing、new。missing 表示终拍没有匹配检测，不直接证明物品离开工位；new 表示仅终拍出现类别实例，不证明是新购资产。未检测到、遮挡和同类替换需应用层增加不确定原因。

当前 AnchorDiff 对 moved/missing/new 的 mask 或 bbox 生成解释区域；稳定对象不整块扣除。bbox 会包含目标周围桌面，可能把其中的杂物变化也当作已解释；分割 mask 较精确但需额外模型或轮廓质量验证。不能声称使用 bbox 就保证不会漏报桌面变化。

9.5 残余区域与实际评分公式

对同坐标图像，计算通道平均绝对像素差 diff。当前阈值为：

threshold = max(12, median(diff) + 4 * max(MAD(diff), 1))
changed_mask = diff > threshold
residual_mask = changed_mask AND NOT explained_mask

残余连通域使用四邻域，记录 bbox、变化像素面积、面积比例和中心点。面积比例不是 bbox 面积比例。残余可以来自杂物，也可以来自照明、显示屏画面、阴影或未被充分解释的仪器边缘。

当前 analyze_pair 路径的实际评分为：

r = residual_area_ratio
n = connected_components
L = largest_component_ratio
k = moved_count + missing_count + new_count
score = min(1,
    0.55 * min(r/0.20, 1)
  + 0.15 * min(n/12, 1)
  + 0.15 * min(L/0.12, 1)
  + 0.10 * min(k/3, 1))

代码同时记录空间熵特征，classify_disorder 的其他调用形式还包含熵项；但当前 analyze_pair 传入字典时熵项为零，因此该路径理论最高分为 0.95。对外字段仍规定为 0–1，不将分数偷偷重新归一化，也不声称现有接口已经按空间熵加权。调整公式须新增规则版本、保留旧结果并重新验证。

当前分数同时计入仪器变化和未解释区域，不是纯杂物面积。若产品未来需要“仪器位置分”与“桌面残余分”分别显示，可新增两个来源清晰的分量，不能把现有总分改名后改变含义。

9.6 质量门控与不可判定

现有基础门控包括梯度能量清晰度、亮度、极端像素比例、对齐置信度和低检测置信度。当前核心门槛包含 blur_score < 5、brightness < 0.05 或 > 0.95、clipped_ratio > 0.25、alignment_confidence < 0.80、任一传入检测 confidence < 0.60。它们是 v0.6.1 代码默认值，不是所有相机的最佳参数。

应用层还必须检查有效基线、锚点数量与几何分布、相机位移、图像 ROI 有效覆盖、手部/人体遮挡、检测突然为空、同类分配模糊、框尺寸异常和视差风险。部分遮挡门控可能需要附加模型，不能把“提示学生移开手”当成已经可靠检测了手。

任何关键门控失败，应用层最终 disorder_score=null，needs_review=true，保存可执行原因和可能的预览框；不把原始低可信分数展示为有效结果。基础结果可以保留在受控 attempt 中用于诊断，但不得与正式最终结论混淆。

10 目标检测训练设计

10.1 数据与标注

先收集真实固定镜头中的仪器，不用网上孤立产品图替代课堂域数据。采样覆盖工位、仪器型号、时段、光照、屏幕内容、角度、相似型号、局部遮挡、空桌、反光和非仪器负样本。短视频可以本地取帧用于采集，但训练数据不能把同一连拍分散到训练与测试集。

每个仪器按统一可见框规则标注类别与 xyxy/YOLO 格式，并记录是否遮挡、截断、反光和来源分组。原始图仅用于受控标注，训练与推理按约定桌面 ROI/坐标处理；如果训练用已对齐图，部署也应使用对应预处理。需要 mask 时单独增加分割标注规范。

划分以工位、采集日期/课次、连续拍摄组和物理仪器为组合分组，先锁定独立测试集，再做训练与验证。最终划分应匹配部署范围；宣称跨工位泛化时，必须有未参与训练的工位测试，不只按随机图片 8:1:1 划分。

10.2 训练路线

微调现成轻量 YOLO 模型，保留初始 CPU/ONNX 基准；先排查数据与标签问题，再调整模型容量或分辨率。无需先从零开发通用目标检测算法。模型选择应依据仪器召回、定位抖动、同类误检、延迟和许可证，不能仅凭 mAP 排名。

训练记录包含数据清单/哈希、类别版本、预训练权重来源与许可、随机种子、超参数、软件版本和验证结果。INT8 量化校准图只能来自训练/专门校准分组，不能使用独立测试集。详细命令、decoder 约定与 RKNN 步骤见训练规范。

10.3 部署验收

同一测试图依次比较 PyTorch、ONNX 与 RKNN 的预处理后输入、原始输出、解码框、NMS 后框和最终对象状态。排查通道、归一化、输入布局、输出布局、padding/scale 和类别映射，而不是只检查模型是否能加载。

记录每类 precision/recall、mAP、定位误差、重复拍照框中心抖动、missing 误报、匹配状态 F1 和 INT8 相对基准退化。检测 confidence 是模型得分，未经校准不直接标为“系统结论准确概率”。

11 接口与数据保存

应用统一使用 RGB uint8 图像、固定桌面比较坐标和像素 xywh 框。固定有效矩形 ROI 的比较图命名为 baseline_registered_pixel，以该裁剪图左上角为原点；原始相机到比较图的复合变换包含裁剪偏移。模型输入的 resize/letterbox 坐标不得流入业务接口。mask 若存在，应为对应比较图大小的二维布尔数组。坐标名称、宽高、ROI、变换矩阵和有效区域都随 capture 保存。

AnchorDiff v0.6.1 的差分面积分母是整幅输入图，没有任意有效区域 mask 的分母参数。首版在基线接受时冻结双方预期可完整覆盖的有效矩形，分析图全幅都是有效桌面区域；若终拍变换后不能完整覆盖该固定 ROI，应重拍或拒答，不能每次缩小 ROI 改变评分分母。未来支持不规则有效区域必须修改算法、记录新版本并重新验证。

12 离线部署与运维

设备首次注册后获取工位绑定与课程授权。正常运行通过内网 HTTPS 同步版本化资料。断网时只开放已缓存且未过期的离线授权，不能把“可离线”理解为任意账号都能登录。资料、模型、规则和会话写入的版本保持一致。

端侧用 SQLite 事务将业务记录与 outbox 事件一并保存，后台同步采用指数退避与抖动，校验时钟异常并同时记录本地顺序。图像上传完成、哈希一致后才能标记事件已同步。服务器不可用不妨碍本地完成，但磁盘将满时阻止新会话并提示运维，不能在没有证据保存能力时继续生成记录。

Linux 服务建议交由 systemd 管理，UI 采用 kiosk 模式，推理服务单独进程。配置进程健康检查、磁盘容量、队列长度、相机失联和温度告警；日志不记录姓名、密钥、完整图片或带凭据 URL。看门狗和自动重启须有重试上限，避免故障循环。

更新先停止接收新会话，等待活动会话结束或记录受控中断，再安装经过验证的签名/哈希发布包；保留上个应用、模型与配置组合，可回滚。数据库迁移先备份并验证恢复，结果记录的版本不能因新软件上线而改写。

13 隐私与网络安全设计

13.1 数据最小化

摄像头物理视野限制在桌面，默认不录音、不保存连续视频、不做人脸识别。短时挑帧在内存中完成，只按策略持久化选中 ROI 与必要失败证据。若人物进入图像，优先拒绝提交并要求移开；不能声称未经开发和验证就已能可靠自动遮脸。

本地与后台仅保存用途所需图像和结构化结果。学员代号是伪名化，不是彻底匿名；身份映射只由授权身份服务提供。显示器、纸张或照片中可见姓名、账号、网络配置等也可能泄露信息，公开演示时必须逐图检查并裁剪/遮盖。

图像 30 天、结构化记录 180 天可作为可调示例，正式周期须由学校按用途批准。到期清理包括本地缓存、后台文件、导出副本和备份到期处理；法律或管理要求保留的记录须有独立依据。删除任务留最小审计，不继续保存已删除内容。

13.2 访问与软件供应链

终端业务 API 默认仅监听本地或受控内网接口；服务端通过校内反向代理 HTTPS，证据存储不公开列目录。证据 URL 须短期有效、绑定权限并防止跨课程下载；URL 中不含身份或长期密钥。管理员与教师会话、设备身份分别管理，设备丢失可吊销凭据。

服务端实施课程级与对象级 RBAC；teacher 直接请求结果更新接口也必须拒绝。设备 worker 使用受限文件权限和独立服务身份。浏览器采用 CSP、适当 CSRF 防护、会话超时、输入校验和禁止任意文件路径；PDF/资料上传校验类型、大小和处理资源限制。

模型权重来自审核后的本地制品，不由运行时自动联网下载未知文件。固定依赖与模型哈希，检查 PyTorch 权重反序列化风险、模型/预训练权重/数据集许可、SBOM 与漏洞更新；不要将 AnchorDiff 的 Apache-2.0 许可自动扩展为检测模型许可证。

导出 CSV 对以 = + - @ 或控制字符开头的文本做公式注入防护，同时保留原值在受控数据库；HTML/PDF 中转义用户字段。导出任务创建和下载都验证授权，失效链接不能继续使用。

13.3 仓库与发布去敏

.gitignore 排除数据、图像目录、身份映射、模型权重、密钥、数据库、日志和导出文件，但忽略规则不能代替内容扫描。提交前检查文件清单、凭据模式、个人信息、真实内网地址、图片 EXIF 与文档作者元数据。

本仓库保持独立本地维护。公开发布时只使用合成或经授权并去敏的例图，不上传课堂原图、姓名学号、设备凭据或校园部署细节。敏感文件已经入历史时不能只删工作区文件，应吊销泄露凭据并按要求清理历史。

质量拒答分别报告坏证据拒答率、好证据误拒率、coverage 与被接受样本错误率；不能只追求低拒答率
容差内残余位置变化 ≤ 0.1 的重复拍照样本单独测试，记录 score/残余面积抖动与漏报风险
残余区域与独立标注变化掩码比较 IoU、区域召回及背景误检；考虑 mask 标注的不确定边界
扰乱度验证无变化低分、变化增加的排序与稳定性；对严重光照/遮挡拒答，不建立虚假的统一整洁真值
INT8 退化和冻结浮点基准比较每类召回、框偏移、状态翻转与拒答；门槛在部署前锁定

正常输入覆盖率建议 ≥ 0.90，同时满足错误率门槛；预先定义的严重质量问题拒答召回建议 ≥ 0.95。所有统一门槛以开发实施与验收计划的冻结版本为准，训练转换的专用回归指标另外报告。

既有 AnchorDiff 合成样例或单元测试只证明实现回归，不能替代真实仪器、真实光照与 RK3588 运行评价。独立测试集在模型和规则选定前冻结；试点中为诊断而看的失败样本不能继续当作完全未接触测试集。

对于二分类误报和召回报告 Wilson 或适当二项置信区间；macro-F1、分数排序与时延按会话/工位分组 bootstrap，避免把连拍帧当成独立样本。低错误率需要足够样本：独立样本中零错误时，95% 错误率上界约为 3/n，此近似只用于规划而非替代正式统计。

智能实验室终端：目标检测训练与部署规范

文档版本：0.1.0（设计基线）

状态：待数据采集、模型训练和实机验收；本文中的性能数值是建议目标，不是已取得结果。

关联项目：智能实验室终端；AnchorDiff v0.6.1（本地基线提交 e5d6798）作为独立、版本化的外部算法依赖。

适用人员：数据采集与标注人员、算法开发人员、端侧部署人员、测试与运维人员。

1. 目的与边界

本模块从实验开始和收台后的图像中识别纳入管理范围的仪器，输出类别、置信度和位置框，为仪器位置变化分析提供观测数据。模块以成熟轻量目标检测模型的迁移学习为起点，不从零编写通用目标检测网络。

目标类别由实际实验室需要确定并可扩展，例如示波器、焊台、直流电源、信号发生器。上述类别是示例，不是限定类别清单，也不要求只能识别 4–6 类。电线、元件、纸张和个人物品默认不做逐项识别，其视觉变化由 AnchorDiff 的残余变化分析处理。

定位标记只用于图像几何定位与对齐。标记编号不得作为仪器资产编号，不通过在仪器上贴标记实现身份识别。检测器的 label 表示类别；检测出的两个示波器属于同一类，不代表系统已知道它们的序列号或实际资产身份。

检测模块不直接判断实验完成质量、电气安全或学生成绩。系统结合检测、位置匹配和残余变化，自动生成相对首次拍照的结果；教师后台只查看与导出。输入不可靠时系统输出“无法可靠判定”并提示重拍，不要求教师在后台修改算法判定。

AnchorDiff 使用的归一化中心位移为：

d = distance(center_before, center_after)
    / max(sqrt(area_before), sqrt(area_after), 1)

其中面积来自同一坐标系中的检测框，单位为像素平方。d <= 0.1 表示落在默认位置容差内。0.1 不是 0.1 像素，也不是桌面宽度的 10%。例如面积为 10,000 像素平方的相同尺寸检测框，中心移动 10 像素时 d = 0.1。不同框尺寸会产生不同的允许位移。

该阈值会受检测框抖动和框尺寸误差影响。数据验证必须覆盖阈值附近的样本，不能仅报告目标检测 mAP。上线时不得为了提高通过率，自动放宽位置容差或悄悄更新本次基线。

3. 模型方案与选型方法

3.1 推荐起点

先选一个可合法使用、可以导出 ONNX、已具有 RK3588 部署参考实现的轻量 YOLO 模型，用实验室自采仪器数据微调。YOLO11n 是可评估的示例起点；也可选择已有更成熟 RKNN 工具链支持的轻量 YOLO 版本。模型版本应由精度、端侧延迟、工具链兼容性和许可证共同决定，不仅看参数量。

先在开发机上建立 PyTorch/Ultralytics 参考结果，再建立 ONNX CPU 参考结果，最后验证 RKNN。RK3588 用于端侧推理，模型训练主要在具有合适 GPU 的工作站上进行；没有 GPU 时可先完成数据整理、少量功能验证或使用获准的训练环境。

方案用途主要收益进入条件
轻量检测模型 + bbox第一版产品标注成本低，训练与部署路径较成熟框定位足以支持位置容差和残余解释
更高输入分辨率或稍大模型定位误差明显时的对照方案可能改善小目标、相似仪器和框定位实测收益超过额外延迟和内存成本
实例分割第二阶段可选仪器轮廓更精确，便于控制残余解释区域bbox 过度遮盖杂物或边缘差分成为主要问题
外观特征与同类拒配同类多实例困难时的增强降低同类仪器错配先建立足够的同类交换、替换和遮挡测试数据

实例分割并非第一版必选。同样不能把 bbox 范围全部忽略，当成“杂物都已解释”：仪器框内可能存在新增线缆和物品。分割或保守边缘策略应有独立的残余变化对照评估。

3.2 模型许可与来源

使用前分别审查训练代码、导出工具、预训练权重、训练数据以及最终产品分发方式。Ultralytics 的开源与商业许可路径应依据所选版本的实际许可文件和官方说明确认；不能因为模型转成 ONNX/RKNN，便推定其许可约束消失。此项形成许可记录，不替代法律判断。

权重只从审核过的官方或授权渠道取得。终端默认读取本地权重，不自动从互联网下载；记录来源 URL、下载时间、许可版本和 SHA-256。不得加载来源不明的 Python pickle 类权重。模型授权、来源或完整性不明确时，不进入上线候选列表。

4. 数据采集规范

4.1 采集单元

数据的最小业务单元是一次受控拍摄场次或一次实验会话，包含开始图像、结束图像及必要的变化描述。用于训练的单图和用于业务验收的图像对分别建立清单，保留二者来源关系。

采集时覆盖实际可能使用的台位、摄像机、安装角度、仪器型号、光照和距离。不要只用同一台仪器、同一块桌面、同一天拍出的连续照片来代表真实部署范围。

建议记录以下去敏元数据：

{
  "sample_id": "sample-000001",
  "capture_group_id": "capture-group-001",
  "session_group_id": "session-group-001",
  "station_group_id": "station-group-A",
  "camera_profile": "camera-profile-01",
  "view_profile": "rear-oblique",
  "split": "unassigned",
  "conditions": ["normal-light", "partial-occlusion"],
  "image_sha256": "<由采集工具计算>",

4.3 数据规模与停止条件

第一批数据用于检查能否学到有效特征，数量由类别差异和现场条件决定。可从每类数百个有效标注实例起步，但这是采集规划量级，不是达到精度的保证。优先增加独立场次、仪器型号和困难样本，再增加同一视频中的相邻帧。

每次迭代按错误类型补充数据：漏检、同类误识别、框抖动、斜视、光照等。只有当分组验证集的关键指标趋于稳定，并且外部台位测试达到门槛，才停止扩充；不能仅以训练损失变低为结束依据。

5. 标注规范

5.1 类别定义

建立 class_catalog，每类包含稳定英文机器标签、中文显示名、包含/排除规则、正反例、类别 ID 和版本。例如 oscilloscope、soldering_station 仅为示例；产品界面使用中文名称，数据和接口使用稳定机器标签。

焊台的主体、支架和烙铁可能分散。第一版建议把“焊台主体”作为目标检测单元，在类别定义中说明哪些附件不纳入框；附件是否归整由残余变化表达。若把附件一起纳入大框，容易使几何中心随摆放变化，不利于 0.1 位置容差。该决策由真实图像对实验确认后固定。

5.2 bbox 规则

  1. 标注仪器主体的可见外轮廓轴对齐包围框，避免包含很长的连接线或手臂。
  2. 对部分遮挡目标，采用统一的“可见轮廓框”或经核实的“完整主体框”政策；二者不得混用。第一版优先选择可见主体框并记录遮挡等级，业务端对明显遮挡门控。
  3. 完全遮挡的仪器不凭记忆画框；该样本保留“无法观测”的质量标签，不能用来证明仪器缺失。
  4. 出画目标记录截断标签。位置比较端应拒绝会影响归位判断的严重截断样本。
  5. 同类多个可见实例逐个标注。所有纳入范围、足够可见的目标均标注，不能遗漏后又作为背景训练。
  6. 负样本对应空标注文件。难以确定类别的目标进入待核实清单，不随意标成背景。
  7. 遮挡/模糊等附加标签单独保存在受控清单中；标准 YOLO 检测文本本身不携带这些质量字段。

YOLO 检测标注格式为 class_id x_center y_center width height，坐标相对原图宽高归一化到 0–1。导入前校验类别范围、框宽高、坐标边界、图像尺寸和重复框。

5.3 标注质量检查

每批由另一名人员抽查标注，错误集中时扩大抽查或重标整批；困难场景全量复核。记录争议原因与规范修订，不只修单张图。对同一张图的双人标注计算类别一致性和框 IoU，用于发现定义差异；该数值是标注一致性，不是模型精度。

标注规范发生实质变化时，更新版本并重新检查受影响的数据。禁止新旧框定义混合训练后仍沿用同一个数据版本号。

6. 数据划分与泄露防护

6.1 分组后再划分

训练、验证、测试以拍摄场次或实验会话为最小隔离组。同一原始图片的裁剪、增强、不同格式、视频邻帧、开始/结束图像必须进入同一划分。数据增强只应用于训练集。

建议初始比例约为训练 70%、验证 15%、测试 15%，可依据独立场次数和类别分布调整。比例不是硬性验收标准；独立性和代表性优先。记录具体随机种子、划分算法、组数、图数和每类实例数。

同时保留两种评估：

  • 已知部署条件测试：测试集与训练集属于预期支持的台位/型号范围，但拍摄会话独立，用于验收日常运行表现。
  • 外部条件测试：保留未参与调参的台位、安装位置或仪器实例组，用于估计迁移表现。未达到门槛时明确不支持相应条件，不能把结果与常规测试混成一个平均值。

若某些样本共享原图、视频、会话或连续拍摄来源，用连接关系合并为不可拆分组后再划分。若要求某台位完全留出，应在组级别整体留出，而不是随机抽取该台位的单张照片。

6.2 测试集封存

测试集不用于选择模型、输入尺寸、置信度、NMS 阈值、位置容差或 INT8 校准。验证集用于调参；最终候选只在已封存测试集上按预先登记的协议评估。

发现测试错误后可以决定下一版本需补充哪些场景，但不得反复针对相同测试样本优化并声称该测试仍是独立验收。新一轮开发应保留旧结果并建立新的独立测试批次。

执行文件 SHA-256 精确去重和感知相似性检查，对跨划分的疑似近重复进行人工确认；保留去重报告。不让测试数据进入训练缓存、主动学习队列或量化校准清单。

7.1 环境与数据目录

7.2 微调示例

以下命令依赖事先安装并锁定版本的 Ultralytics，以及已核实许可的本地预训练权重。local_models/yolo11n.pt 只是示例文件名，命令不会凭空产生这些数据或权重。PowerShell 中可单行执行：

yolo detect train model=local_models/yolo11n.pt data=local_data/instruments_v1/dataset.yaml imgsz=640 epochs=100 batch=8 seed=42 project=runtime/model_runs name=detector_v1

epochs=100、batch=8、imgsz=640 是初始实验参数，不是最佳配置。训练期间使用验证集观察每类漏检和框定位，保存训练日志、实际超参数、最佳检查点与最后检查点。随机种子有助于复现，但 GPU 算子和工具链可能仍非完全确定，必须记录实际环境。

增强从实际扰动出发：适度亮度、对比度、颜色和小幅几何变化。夸张旋转、镜像、强透视和裁剪应有现场合理性；避免把物理上不可能的仪器形态变成主要训练数据。训练增强不能代替真实光照、真实斜视和新型号采集。

7.3 验证与模型选择

yolo detect val model=runtime/model_runs/detector_v1/weights/best.pt data=local_data/instruments_v1/dataset.yaml split=val imgsz=640

选择模型时同时看每类 precision、recall、mAP50、mAP50–95、误检类型、框中心误差和业务位置判定。不能用一次聚合 mAP 抵消某个关键仪器类别的持续漏检。

只有在锁定模型、预处理、阈值和业务规则后，才运行最终测试：

yolo detect val model=runtime/model_runs/detector_v1/weights/best.pt data=local_data/instruments_v1/dataset.yaml split=test imgsz=640

每次实验建立登记项：数据版本、划分版本、代码提交、模型配置、初始化权重哈希、训练参数、验证结果和是否进入候选。不得凭训练命令成功便称“模型已经可部署”。

8. 对齐、预处理与坐标规范

8.1 推荐应用链路

开始/结束原始图像
→ 图像质量与标记可用性检查
→ 镜头畸变校正（已标定时，两图一致）
→ 将结束图像对齐到开始图像的基线平面
→ 验证已冻结固定矩形 ROI 的全部像素有效及几何质量
→ 从两张同坐标图像裁出相同的固定比较矩形
→ 在两张比较图上分别检测
→ 还原模型输出到同一比较图的 baseline_registered_pixel 像素坐标
→ 调用 AnchorDiff 做匹配与残余分析
→ 在固定 ROI 比较图上绘制解释框和残余区域

对齐之后检测是当前集成的关键约束。AnchorDiff v0.6.1 的配对分析会变换图像，但不能假定它同时变换应用传入的最终检测框或掩膜。应用应先完成对齐，并防止调用时重复应用几何变换；外部对齐的参数、误差与有效 ROI 仍需在业务记录中保存。

固定 ROI 随相机配置/本次基线冻结，记录裁剪原点与输出宽高。最终固定 ROI 比较图直接命名为 baseline_registered_pixel，其左上角为 (0, 0)；首次基线标准 frame 从建立时就是经过有效性检查的该裁剪图。开始与结束使用完全相同矩形，不能按每次结束图像的有效范围动态缩小或平移 ROI，否则面积比例和对象位置失去可比性。变换后该固定矩形内有无效填充像素、缺失区域或不满足覆盖条件时，应用拒答并提示重拍；不通过将黑边当作桌面来继续评分。

AnchorDiff v0.6.1 的残余差分面积比例分母是传入比较图的整幅像素数，未提供任意有效掩膜下的有效面积分母。第一版因此以经过有效性检查的固定矩形裁剪作为完整比较输入。检测框、掩膜、残余区域进入 core、归档和叠加时均使用同一 baseline_registered_pixel 坐标，不另保留名称相同的全图坐标。原始 camera_pixel 到比较图的复合变换记录包含去畸变参数、warp 及裁剪 offset；不能将原始相机框或未裁剪全图框直接传给 core。未来若支持不规则有效掩膜及有效面积分母，须发布新的算法/配置版本，重新验收，不沿用本版分数含义。

对几帧连续照片，先挑选合格帧，再对被选中的实际帧检测。不能把另一帧的框直接复用到所选图像，也不能向整段序列传同一套结束检测结果。

斜视下，桌面单应性不能消除高仪器的全部视差。摄像机发生移动时，仪器上表面可能相对桌面标记产生假位移。因此应优先固定相机、避免安装结构晃动，并以真实高仪器测试界定允许相机运动；不能凭桌面标记重投影误差低就宣布所有仪器已准确对齐。

8.2 输入约定

内部图像建议统一为 H × W × 3、RGB、uint8；相机输出的 BGR/YUV 由采集层显式转换。每个模型适配器根据其框架要求转换，不假定所有库对 NumPy 图像都按 RGB 解释。用红/蓝色块夹具检查通道顺序，用非正方形图像检查宽高顺序。

统一显式记录模型宽高，如 model_width=640、model_height=640。接口中约定 image_shape=(height, width)，避免将 input_size 的宽高解释混淆。AnchorDiff 现有适配器对输入尺寸和直接 resize 的行为应通过实际测试核实，尤其非方形输入。

对于 YOLO 常见的 letterbox 预处理，记录缩放和填充：

r = min(model_width / image_width, model_height / image_height)
new_width  = round(image_width × r)
new_height = round(image_height × r)
pad_left、pad_top = 实际使用的左、上填充值

解码后逆变换为：

x_original = (x_model - pad_left) / r
y_original = (y_model - pad_top) / r

填充舍入、是否拉伸、是否除以 255、输入 layout、插值方法和颜色顺序必须与训练/参考推理一致。框还原后裁剪到有效图像范围，再转换成 x, y, width, height。不得把归一化模型坐标直接当原图像素，也不得只逆变换 bbox 而遗漏实例掩膜。

9. 导出与 ONNX 验证

9.1 导出示例与版本约束

先选择 RKNN-Toolkit2 当前版本明确支持的 ONNX 算子与 opset，再锁定导出参数。下面给出一个静态输入、原始输出的示意命令；opset=12 仅为可验证起点，不保证适用于每个模型或工具链：

yolo export model=runtime/model_runs/detector_v1/weights/best.pt format=onnx imgsz=640 opset=12 dynamic=False simplify=False nms=False

记录导出工具版本、输入/输出名称、shape、dtype、opset 和模型哈希。ONNX 图能被加载只证明格式可读，不证明预处理、解码或业务效果正确。

9.2 模型专用后处理

不同 YOLO 版本和导出方式可能返回 [1, 4+classes, candidates]、多尺度特征图或已完成后处理的结果。不能根据“YOLO”名称套用一个固定输出假设。通过模型元数据、官方实现和实际输出共同确认：框是 xywh 还是 xyxy，分数如何组成，是否含 objectness，是否需要 sigmoid、DFL、anchor/grid 或 stride 解码。

处理顺序固定为：原始 head 解码 → 类别置信度计算 → 置信度过滤 → 按约定执行 NMS → letterbox 逆变换 → 图像边界检查 → 类别 ID 映射 → 统一 Detection 输出。记录 NMS IoU 阈值、是否按类别抑制、最多保留框数以及同分时的排序规则。训练/ONNX/RKNN 的后处理尽量共用代码。

AnchorDiff v0.6.1 的 ONNX/RKNN 默认解码器只面向行式 [x0,y0,x1,y1,score,class_id] 输出，不能直接解释原始 YOLO head；现有直接 resize 预处理也不等于 letterbox。实际接入可在本项目实现符合 Detector.detect() 协议的完整适配器，再传给 AnchorDiff，不要求修改独立公开算法仓库。

9.3 一致性门槛

在固定验证夹具上对比参考模型与 ONNX：输入张量、输出 shape、检测类别、中心坐标、框 IoU、置信度和漏检。夹具必须包含非方形图、边缘目标、负样本、同类近邻、重叠框和通道检查图。

对于阈值附近的数值差异，区分浮点误差与后处理错误。建议初始回归门槛：高置信匹配目标中心误差中位数不超过有效图像对角线的 0.2%，且典型目标框 IoU 不低于 0.98；这是转换一致性目标，应按具体模型和有效图像尺寸调整、冻结并留档，不能当作真实标注精度。

ONNX 验证失败时先修坐标、预处理与解码，不通过重新训练掩盖软件错误。

10. RK3588 / RKNN 部署规范

10.1 工具链分工

模型转换在符合 Rockchip 官方支持条件的主机环境进行，运行在 RK3588 开发板。板端系统、NPU 驱动、RKNN runtime 与转换工具版本按厂商兼容要求固定。Windows 开发机可使用合适的受支持 Linux 环境转换，不承诺 Windows 本机可直接执行所有 RKNN 工具。

先进行非量化或工具链支持的较高精度转换对照，再评估 INT8。使用 Rockchip 对应模型参考实现作为解码依据，但必须核对其模型结构、类别数和导出版本与本项目相同。

AnchorDiff v0.6.1 的默认 RKNN runtime 构造代码需要核对实际包 API；常见板端 API 类名为 RKNNLite。建议应用自己构造已验证 runtime 并实现检测适配器，或按所用版本修正适配方式。不能将安装某个可选依赖等同于“上板即用”。

10.2 INT8 校准

校准图像仅从训练分组或预先单独划出的训练校准分组选择，不使用封存测试集。覆盖实际光照、仪器类别、背景和空场，避免只选择正常明亮图片。清单记录图像哈希、分组和预处理。

校准样本量根据官方工具要求和验证曲线选择；可从数百张有代表性的训练图像起步，但不能把这个量级当作充分性证明。确保校准与推理使用一致的颜色、缩放和归一化策略，防止工具链配置与应用层重复除以 255 或重复减均值。

INT8 模型通过后，重新评估检测和图像对业务指标。建议转换回归门槛：相对参考模型的 mAP50–95 下降不超过 0.02（绝对值），每类 recall 下降不超过 0.03，仪器错误“缺失”率增加不超过 0.01。若不满足，排查校准分布、算子与量化敏感性，再评估更高精度方案；这些数值属于初始验收建议。

10.3 端侧运行检查

检查项要求与证据
完整性启动验证本地模型和类别文件哈希，缺文件或不匹配则不启用判定

输出保存去敏的 shape/dtype 诊断，模型不兼容时返回结构化错误

当前没有 RK3588 实测数据。按《开发实施计划》的统一建议基线，合格输入条件下“收台拍照至结果显示”p95 不超过 5 秒，以选定摄像机分辨率、输入尺寸、板卡和 UI 负载完成至少 200 次端到端测量，并完成连续 8 小时运行。NPU 的标称算力不能替代端到端实测。

10.4 端侧判定与服务端归档

默认由受管终端 worker 完成采集、推理和判定，断网时保存结果和证据到本地待同步队列。服务端校验受管设备身份、worker 来源、输入/模型/配置摘要、schema 与允许的版本组合，随后归档原始结果；教师浏览器不直接提交或修改判定结果。

哈希证明文件内容一致，不独立证明结果由可信 worker 生成。设备注册、受控凭据和经认证的传输用于来源校验，哈希用于数据关联与完整性检查。同步结果携带 attempt_id、backend_id、软件/模型版本和输入摘要，重复同步按幂等键返回同一归档记录。

服务端复算仅作为可选验证任务，创建独立 attempt 并标注所用 backend，不能覆盖端侧原判定。CPU、ONNX 与 RKNN 可能出现浮点或量化差异，不假定结果逐位一致；根据预先冻结的转换与业务一致性门槛比较，差异保留在审计记录中。

11. 统一检测接口与质量拒答

11.1 对 AnchorDiff 的输出

统一结构为 Detection(label, bbox, confidence, mask=None)；bbox 使用最终固定 ROI 比较图的 baseline_registered_pixel 像素 x, y, width, height，原点是该图左上角 (0, 0)。mask 若存在则为该比较图全幅布尔掩膜。core 输入、归档对象、残余区域和叠加输出使用完全相同坐标，不在归档时另加 ROI 原点。

{
  "label": "oscilloscope",
  "bbox": [320.0, 180.0, 240.0, 160.0],
  "confidence": 0.93
}

适配器验证 confidence 在 0–1、坐标有限、宽高为正、类别合法，不接受 NaN 或非法类别 ID。模型异常与“没有检测到对象”分开返回，不能把推理失败转换成空列表。

业务外围另保存检测诊断：模型哈希、阈值、候选数、各阶段耗时、有效 ROI、图像质量、检测稳定性及错误码。不要给 AnchorDiff 伪造额外构造参数；附加业务元数据放在本项目封装层。

11.2 不确定输入的处理

以下至少进入重拍或 needs_review，不输出有把握的归位结论：

  • 图像模糊、曝光异常、有效 ROI 过小或无法可靠对齐。
  • 定位标记不足、配置不一致、强相机运动或高物体视差超出验证范围。
  • 手部/人体或遮挡物覆盖仪器关键区域，目标严重出画。
  • 原本可见仪器在结束图中未检出，但存在低置信候选、严重遮挡或多帧不一致。
  • 同类多实例无法可靠对应，疑似同类替换或高成本强行匹配。
  • 模型未支持的类别/角度、推理失败或输入输出契约不一致。

检测器置信度不是“仪器确实在场的概率”。某目标没有检测框，也不能单独证明它不存在。若采用低/高双阈值，高阈值用于可靠候选，低阈值候选保留供不确定性检查；两者通过验证集校准，不与位置容差 0.1 混用。

AnchorDiff v0.6.1 对传入的任何置信度低于 0.60 的 Detection 会触发检测置信度门控。因此低置信候选保存于本项目应用层，先用于漏检、遮挡和不稳定检查，不直接与可靠 Detection 一起传入 core，否则会使原本可分析的场次整体拒答。若应用配置可靠阈值低于 0.60，应在版本兼容校验时拒绝该配置，或以新算法版本明确重新定义门控；不得篡改/抬高原始置信度绕过门控。原始推理失败始终为结构化错误，不能转换成“成功但空检测”。

可对每次拍照采集短帧组，并比较对象检测的类别、框位置与数量稳定性；这用于筛选可靠输入，不意味着必须实时视频跟踪。多帧策略改变后，重测拒答覆盖率和完整业务指标。

现有 AnchorDiff 已有部分图像与检测置信度门控，但并未完整实现上述手部遮挡、标记缺失、空检测和强运动策略。本项目需要补充并验收，不能仅在界面文案中声明已支持。

14. 数据与安全管理

原始图像、标注、真实身份映射、训练缓存、模型权重和运行数据默认不提交 Git。仓库保存去敏模板和可复现流程；受控数据目录有最小权限、留存期限、删除记录和备份策略。预训练及最终权重体积不大也不改变该策略。

数据采集端避免记录真实用户身份，数据训练集不包含姓名、学号和账户信息。若图像含仪器序列号、网络配置、屏幕敏感内容，采集前遮挡或按可审计规则去敏；遮挡处理可能影响检测，应记录处理版本，避免在训练与产品推理间产生未说明的分布差异。

上传和读取图像设置大小、格式、像素总量与路径限制，拒绝路径穿越；不把用户文件名直接当存储路径。不在日志输出原始图像内容、完整身份或凭据。模型转换只处理可信模型，不对外开放任意模型执行接口。

更新候选模型经过离线验证，终端验证包完整性并原子切换。身份映射与算法数据分离，教师查看权限不包含模型更新、训练集导出或判定记录修改。导出的模型报告使用去敏字段，含 CSV 时转义以 = + - @ 开头的文本字段，防止电子表格公式注入。

1. 业务边界与术语

系统流程为：登录并选择实验 → 首次拍照 → 记录仪器类别与位置 → 查看资料与清单 → 完成实验并点击结束 → 收台向导 → 结束拍照 → 系统分析 → 教师查看记录 → 导出报告并线下反馈。

  • 基线：系统按冻结的选帧策略，从本次首拍候选短序列中选出的首份合格 capture，以及它的检测结果、相机参数和版本快照。先按质量排序或打分选帧、再固定基线的具体策略须版本化；不能按事后扰乱度选择基线。基线描述当时的桌面，不证明桌面符合任何整洁标准。
  • 仪器：配置类别表中需要视觉记录的对象，例如示波器、焊台、电源。类别可根据实验室实际使用扩展，不要求事先限定为 4–6 类。
  • 位置参考：基线中对象的图像位置。无需预设固定归位区；结束时允许小幅位移。
  • 定位标记：用于计算相机与桌面之间的几何关系。标记 ID 不表示仪器身份、学生身份或物理资产编号。
  • label：检测模型的类别名称。两台同类仪器可以有相同 label，因此 label 不等于 asset_id。首版不保证辨认同类仪器是否发生物理替换。
  • attempt：一次确定输入、确定版本的分析执行记录。重新拍照或重新分析创建新的 attempt。
  • 正式结果：由受管视觉 worker 生成、经过归档校验并由系统选定的 attempt。教师没有修改或选择正式结果的权限。
  • needs_review：算法或应用门控无法给出可靠结论。界面文案使用“暂不可判定／请重拍／需设备维护”，不把它解释为教师人工评分流程。

视觉识别只记录仪器。线缆、小器件、个人物品等可以表现为未解释残余变化，不根据残余区域自动命名为某个具体物品。材料清单属于教学资料，清单勾选不构成视觉识别结果。

离线已完成的端侧有效分析可以在本地进入 FINALIZED，同时处于 pending_sync。网络断开不应把本来有效的 disorder_score 改为 null。相反，任务执行成功但质量门控失败，可以是 execution_state=SUCCEEDED、decision.status=indeterminate、needs_review=true、disorder_score=null。

3.3 基线、attempt 与正式结果选择

  1. 每次拍照产生新的 capture ID；原始字节、哈希和元数据不可覆盖。
  2. 系统按冻结的选帧策略，从首拍候选短序列中选择首份合格 capture，并固化 baseline_capture_id、比较矩形 ROI 和图像尺寸。接受之后不能静默改为另一张更容易得到低分的基线，也不能在不同 attempt 中缩小 ROI。
  3. 如果已经固化的基线后来被发现损坏，当前会话应记录为基线无效；不能改用结束照片当基线。重新开始实验须建立新会话并保留关联原因。
  4. 每次终拍／重新分析创建递增 attempt_no；输入包含明确的基线 ID、终拍 ID、预处理图像 ID、版本快照和输入摘要。
  5. 终拍自动选帧应先做质量检查、选定 capture，再在选定且对齐后的图像上执行检测。不能把同一组检测框套用到多个候选帧。
  6. 学生正常流程由系统选择第一个通过全部门控的有效 attempt；不可由学生比较多个分数后任选低分。选定后如需复算，由运维提交有理由的任务。
  7. 历史 attempt 全部保留。正式结果变化使用新的 finalization_event，记录新旧 ID、系统选择理由和发起任务；原 attempt 不变。
  8. 教师导出的报告固定所选 attempt 和时间快照；后续复算不改变已经生成的文件。新报告必须显示新 attempt ID。

4. 图像与算法输入契约

4.1 坐标、颜色与几何

所有传入同一次 analyze_pair 的图像、bbox 和 mask 必须处于同一个 baseline_registered_pixel 坐标系。该坐标系是基线建立时冻结的有效矩形 ROI 所对应的分析图像坐标，ROI 左上角为 (0, 0)，x 向右、y 向下，单位为像素；数组形状为 height × width × channels。相机原图到这个坐标系的畸变校正、裁剪偏移与变换关系必须保存。

  • bbox 使用 [x, y, width, height]，不能混用 xyxy。范围是半开区间 [x, x+width) × [y, y+height)，宽高必须大于 0。
  • 检测前预处理统一 RGB；OpenCV 的 BGR 输入必须显式转换。模型训练和部署的归一化、通道顺序、letterbox、padding 和 NMS 必须记录在模型包中。
  • bbox 可保留浮点数；绘图阶段再按统一规则取整并裁剪到有效图像区域。模型输出为超界、NaN 或 Inf 时拒绝接入。
  • mask 如存在，必须与比较图像大小完全相同；外部存储二值 PNG 或无损编码，记录工件 ID 和哈希，不能用 JPEG 保存 mask。
  • comparison_roi 是基线接受时冻结的有效矩形。首版先在基线坐标中选择矩形并裁剪为分析图像，因此传给 AnchorDiff 的全幅均为有效桌面区域，分母为该分析图像的 width × height。所有 attempt 复用同一矩形和尺寸，不可逐次缩小 ROI 改变分母。
  • 结束图像对齐后，必须检查来源像素能完整覆盖冻结矩形；存在变换黑边、无来源像素或插值所需邻域超出来源图时，应用拒答并要求重拍。源图有效性 mask 可用于应用覆盖检查，但不作为 AnchorDiff 分母 mask 传入。
  • 当前 AnchorDiff core 没有任意 comparison_roi mask 参数，区域比率以整幅分析图面积为分母。未来若支持任意形状 ROI 或遮挡区扣除，必须先升级算法并给出新的分母、评分与 schema 版本，不能仅在应用元数据里增加 mask 后声称算法已经使用它。
  • 原始相机图使用 camera_pixel 坐标；单应性作用于畸变校正后的桌面平面图，不能把非线性畸变校正假装成一个单应矩阵。对外保存的 camera_pixel → baseline_registered_pixel 复合 transform 必须包含畸变校正、平面配准和冻结 ROI 的裁剪偏移。裁剪后的 bbox 不得和未裁剪全图框使用同一坐标标签。
  • 斜视时单应性仅对桌面平面成立。高仪器存在视差；相机位置明显改变或视差导致定位不可靠时应拒答，不能声称全景已被精确校正。

AnchorDiff 集成约束：当前 analyze_pair 会变换 final 图像，但没有自动同步变换外部提供的 final bbox／mask。应用推荐先校正和对齐两张图，检查结束图像完整覆盖冻结矩形，裁剪为尺寸固定的统一分析图，随后对两张图执行检测，再向 AnchorDiff 传同坐标图像与检测结果；此调用不再让 AnchorDiff 二次变换图像。应用自己保存定位标记、实际变换质量、来源覆盖率和几何门控证据。此时 core 可能输出恒等路径的 alignment_confidence=1.0、geometry=null，它们不代表外部配准已验证成功；正式结果必须独立通过外部几何门控。残余叠加图必须基于该对齐裁剪图生成；若显示原始终拍图，需要将 mask／bbox 反变换。

4.2 位置容差

默认 position_tolerance = 0.1。对于匹配对象：

displacement = distance(center_before, center_after)
               / max(sqrt(area_before), sqrt(area_after), 1)
stable 当且仅当 displacement <= position_tolerance

这是对象尺度归一化的无量纲位移，不是 0.1 像素、桌宽的 10% 或扰乱度阈值。因为 bbox 面积受角度、遮挡与检测误差影响，必须通过实拍样本评估容差边界附近的稳定性。显示可四舍五入，判定必须使用未舍入的数值。

4.3 应用质量门控

AnchorDiff 自身质量证据与应用门控分别保存。应用还须实现并验证：标记可见性、相机标定有效性、拍摄区域是否被手或身体明显遮挡、冻结矩形的完整来源覆盖、异常空检测／检测计数下降、定位歧义和大幅相机移动。外部配准的重投影误差、归一化误差、矩阵退化／病态检查及实际 confidence 必须保存并独立门控；不能因为 core 在已对齐图上返回 1.0 而跳过这些检查。不能把现有梯度、亮度和检测置信度指标说成完整遮挡检测。

任何关键门控失败，应用的 decision.status=indeterminate、decision.disorder_score=null。原始 anchordiff_result 按实际返回保留，不能为了统一界面篡改内部对象状态或删除质量警告。

5.4 schema 验证规则

  • 用 JSON Schema／Pydantic 等对输入输出做结构验证；外部请求禁止未知的敏感写入字段，worker 的版本化原始 evidence 可在独立命名空间保留。
  • 分数、位移和质量数值必须有限；禁止 NaN、Inf 以及字符串伪装数字。disorder_score 为 null 时，所有展示层和导出层均显示“暂不可判定”，不能转成 0。
  • object_index 必须落在当前原始 objects 数组范围内；摘要计数必须与数组状态一致。
  • objects／residual_regions 与图像范围、对象 mask 大小、冻结矩形尺寸必须一致。首版区域比率分母为整幅分析图的 width × height；同会话各 attempt 不允许不同 ROI。未来分母定义变化须记录新的预处理／算法版本，不能跨版本混算。
  • 原始结果与应用决定的约束在服务端再次验证。任何重复 ID 不同 hash、对象状态非法、版本未知或归属不一致的包都进入冲突／隔离处理，不能静默采用最新值。

6. API 约定

6.1 通用协议

  • 后台路径前缀 /api/v1，全程 TLS。终端本地接口建议使用操作系统本地 socket；如采用 loopback HTTP，必须校验认证与 Origin，禁止绑定全网卡裸露写接口。
  • GET 不改变业务状态；POST 创建资源或执行受权状态转换。教师端没有结果 PUT/PATCH/DELETE 路由。
  • 创建会话、结束、拍照、分析、重算、同步和导出请求必须带 Idempotency-Key。服务端以 (principal, method, normalized_route, key) 为唯一键，保存规范化请求体摘要和响应。
  • 相同 key、相同请求体返回原响应；相同 key、不同请求体返回 409 IDEMPOTENCY_CONFLICT。客户端重试不得自动换 key 造成新任务。
  • 会话转换使用 expected_revision／If-Match，在事务中比较版本并更新。过期版本返回 409 STATE_CONFLICT；用户重复“结束实验”返回已存在的结束事件，不重复触发拍照。
  • 列表使用有上限的 page_size 和 cursor；导出另走异步任务，禁止“无分页下载所有学生”。IDOR 防护在每个对象读取、图片下载和导出时执行。
  • 时间统一传 UTC ISO 8601。记录 device_captured_at、server_received_at、clock_offset_ms／clock_trusted，课程页面按配置时区显示。
  • 错误响应不含堆栈、服务器路径、完整 SQL、设备密钥或学生名单。

401 AUTH_REQUIRED登录过期、设备凭据失效重新认证；不丢弃本地队列。
403 ACCESS_DENIED非授权课程、工位、角色或过期离线授权停止该操作；不放宽权限。
404 RESOURCE_NOT_FOUND资源不存在或不应向当前用户暴露使用统一响应防止枚举。
409 ACTIVE_SESSION_EXISTS工位已有活动会话恢复原会话，不新建替代。
409 STATE_CONFLICT状态／revision 不允许该动作刷新并按当前状态继续。
409 IDEMPOTENCY_CONFLICT同 key 不同请求体记录客户端逻辑错误。

413 PAYLOAD_TOO_LARGE图像／批次超过上限拆批或调整捕获配置，不绕过上限。
415 UNSUPPORTED_MEDIA_TYPE非允许图像／文档类型拒绝文件。
422 QUALITY_GATE_FAILED同步调用的候选拍照未通过门控展示原因并请求重拍；异步任务在 job 中表达。
422 VERSION_NOT_APPROVED未发布模型／配置、schema 主版本未知运维修复部署；不改用任意默认模型。

业务不可判定不一定是 HTTP 错误：analysis job 执行完成后可返回 200／任务成功，结果中的 decision 指明不可判定。失败重试采用指数退避及抖动，不无上限忙轮询。

8. 离线运行、同步与恢复

8.1 离线授权

离线模式只允许使用事先下发、签名且未过期的缓存包。包应包含绑定设备／工位、课程与实验版本、已授权学员伪名／小组、授权时间窗、身份验证材料、配置／模型版本和资料 hash。禁止“断网就允许任何账号”或凭一个工位码冒用任意学生。

缓存名单本身不等于身份验证。建议离线使用校验过的校园卡映射、限时签名凭据或专门的离线登录方案；普通用户名不能直接通过。若采用口令验证器，必须遵循密码存储规则并限制尝试，不能缓存明文密码。具体认证方式需由部署方确认。

授权过期、名单缺失、时钟可信性丢失或配置包签名无效时，拒绝启动新会话并给出具体提示；已经开始的会话按预先确定的恢复策略完成本地留痕，并在同步时标记授权时效证据。服务器不得为了接纳历史数据自动扩大课程权限。

8.2 同步顺序与冲突

上传会话/事件 manifest
→ 上传缺失原始与派生工件
→ 后台校验大小、类型和SHA-256
→ 上传完整 attempt 结果包
→ 校验工位、授权快照、版本和输入依赖
→ 归档并返回逐项ACK
→ 端侧标为synced

支持至少一次传输和乱序到达；依赖未就绪的结果进入 pending_dependencies，不会被当作完整正式记录。工件全部校验前不得暴露教师图片链接或有效报告。

  • 同 entity ID、相同 hash：返回已接受 ACK，不重复创建。
  • 同 entity ID、不同 hash：保留本地原件和后台证据，返回冲突；不得“最后写入覆盖”。
  • 相同图片字节可做存储去重，但不能因此把不同课程的权限合并，或向一个用户暴露另一个用户已上传的 hash。
  • 服务端收到晚到的旧 attempt 不改变当前正式指针；以系统 finalization 事件和版本比较处理，不能按最新接收时间选结果。
  • 设备时钟漂移时保留拍摄时序、设备序列号和服务器接收时间，标记时间可信性；不要按错误时间把学生归到其他课次。

8.3 崩溃恢复

相机写文件采取临时文件写入 → flush／关闭 → 哈希 → 原子 rename → 数据库事务登记的顺序。重启扫描未完成 manifest 和临时工件，区分可恢复任务与孤立文件，不凭文件存在推断分析成功。

分析任务以 (session_id, capture_id, input_manifest_hash) 幂等执行。重复启动只能继续同一任务或产生有理由的新 attempt；不能复用旧 attempt ID 写入不同模型结果。终端重启后恢复活动会话、收台阶段和待同步队列，学生重新认证后继续操作。磁盘不足时阻止新拍照并保护未同步证据，不能默默删除当前基线。

9. 图像、导出与去敏

  1. 摄像头覆盖范围限定桌面，安装验证应检查人脸、相邻桌面和屏幕是否落入画面。原始照片若意外包含额外个人信息，按留存策略受控保存／清理；默认只向教师显示裁剪到有效桌面的证据。
  2. 所有图像、结果、报告都保存为非公开资源。短期 URL 只能指向具体授权工件，不能允许目录列表或任意路径；URL 有效期短且只读，日志和分享内容不能记录完整可用 token。
  3. 下载 API 每次重新检查课程权限。签名 URL 已发出后通常在过期前仍可用；如果部署要求即时撤权，使用后台鉴权流式下载代替直接签名 URL。
  4. 身份与视觉证据使用伪名关联，身份映射单独限制；Git、示例、测试数据、日志、错误截图和公开文档中不放真实学生信息、真实实验图片或密钥。
  5. 资料展示禁止主动执行上传文档中的脚本。对 HTML/PDF 预览、文件扩展名与 MIME 做允许列表检查；后台抓取远程资料地址需防止访问内部管理网络。
  6. CSV 导出中的所有文本字段，若去掉前导空白／控制字符后以 = + - @ 等公式触发字符开头，必须转义并按目标电子表格验证。姓名、仪器类别、解释文本和文件名都不能直接进入公式上下文。合法数值分数按数值列输出，null 显示空值和明确不可判定原因。
  7. 报告必须显示“相对本次基线的可见变化”；不能把扰乱度当概率、卫生合格、安全合格、实验完成质量或学生成绩。不可判定记录单列，不参与默认均值，统计报告注明有效记录数、总记录数与拒答比例。
  8. 留存期限由学校／部署方配置，图像、结果摘要、身份映射和导出文件可采用不同期限。清理任务要覆盖端侧、后台、对象存储和导出缓存；备份采用单独可解释的到期策略。不得在设计文档中承诺已经满足某一法规认证。

架构：终端负责采集、图像质量检查、端侧分析、学生交互和断网缓存，本地完成会话，后台同步状态独立。后台保存版本化记录并提供教师只读查询，默认不重新计算；如启用服务端复算，必须创建新分析 attempt 并保留原结果。AnchorDiff 作为独立外部算法依赖接入，实验室业务、身份数据和现场图片保留在本仓库对应的私有部署中。

建议技术栈：Python、FastAPI、OpenCV、AnchorDiff、ONNX Runtime 或 RKNN Runtime、Vue/TypeScript、终端 SQLite、后台 PostgreSQL。版本需在各阶段以实际兼容结果锁定。

本计划规定交付顺序、接口门禁和验收证据。文中的工期、样本量、精度、延迟和容量均为建议规划或验收目标，不表示当前已经实现或验证；进入试点前必须用实际设备和现场数据确认。

1. 全局约束

  1. 流程为：登录/选实验 → 首次拍照 → 记录仪器及位置 → 资料与清单 → 学生点击结束 → 收台向导 → 结束拍照 → 系统判定 → 教师只读查看 → 导出报告线下反馈。
  2. 只对仪器做目标检测和位置记录。小器件、线缆和个人物品可以表现为残余变化，不要求逐件识别。
  3. 标记只用于相机定位及图像对齐，不作为仪器身份标签。
  4. 本次合格首拍是比较基线，不预设固定归位区，也不把限定 4–6 类仪器作为启动条件。
  5. 默认位置容差为 0.1。归一化位移为中心点欧氏距离除以 max(sqrt(before_bbox_area), sqrt(after_bbox_area), 1)，不是桌面宽度的十分之一。
  6. 扰乱度为相对基线的 0–1 分数，越高表示未恢复变化越多；不解释成学生成绩、事故概率、安全合格结论或绝对整洁等级。
  7. 质量门控失败时返回 disorder_score=null、needs_review=true 和原因。学生可在首次终拍之外最多额外重拍 3 次，持续失败交由运维排查；教师只能查看，不能改分或改算法结论。
  8. 同类目标匹配不等于确认物理资产身份；同类替换、遮挡及无法匹配情况必须保留不确定性。
  9. 固定或基本固定的相机是前提。后上方斜视可试用，但平面单应性不能消除高仪器的视差，必须以实际安装高度、镜头稳定性和定位误差验收。
  10. RK3588 是候选端侧平台，上板兼容性、速度、温度和长期稳定性尚需实测；模型训练在具有合适算力的开发主机进行。
  11. AnchorDiff 公开库与本系统保持项目边界，不向其公开仓库加入实验室身份、课程、台位、现场数据或业务文档。
  12. 本仓库当前仅本地建立，文档交付不等于授权公开发布代码、数据、权重或实验室信息。
  13. 首版在首拍时冻结有效矩形 ROI，裁剪后的整幅分析输入即评分分母；同一会话各次 attempt 使用相同 ROI 和尺寸。结束图无法覆盖完整冻结 ROI 时拒答，禁止为了通过分析按 attempt 缩小 ROI。

本设计核实的 AnchorDiff 基线为 v0.6.1、commit e5d6798。接入时锁定完整提交哈希及依赖版本，不通过浮动分支自动升级。现有 analyze_pair 的规则分支未纳入熵项，权重和为 0.95；输出仍属于 0–1 域，但不把实际可达上限承诺为 1。后续纳入空间熵或重标定分数时必须更新 rule_version 并重新评估。

检测框为分析图坐标系中的 x,y,width,height，mask 大小与分析图一致；图像和标签必须携带 image_id、coordinate_space_id、宽高以及转换版本。未通过质量或几何门禁时停止后续判定，不制造空检测后再推导“全部缺失”。

正式会话 lifecycle 使用下列枚举，不与同步状态混用：

状态含义与正常出口
AWAITING_BASELINE等待合格首拍；成功进入 IN_PROGRESS
IN_PROGRESS学生进行实验；点击结束进入 CLEANUP
CLEANUP收台向导；确认后进入 AWAITING_FINAL，正常流程不得返回实验进行状态
AWAITING_FINAL等待结束采集；成功进入 ANALYZING
ANALYZING端侧执行当前 attempt；可靠结果进入 FINALIZED，质量失败进入 RECAPTURE_REQUIRED
RECAPTURE_REQUIRED引导学生额外重拍；有余量时进入 AWAITING_FINAL，额外重拍 3 次仍失败进入 INCOMPLETE
FINALIZED已有不可覆盖的可靠结果；后台同步单独进行
INCOMPLETE收台结束但无法可靠判定或证据不完整；保留空分数、原因和已产生的 attempts
CANCELLED尚未进入 IN_PROGRESS 时受控取消，留最小审计；实验开始后异常关闭进入 INCOMPLETE

额外重拍上限为 3 次，即最多 1 次首次终拍加 3 次额外终拍。已完成会话的常规学生界面不能重开实验；可选服务端复算只能生成新 attempt，不能覆写已存在结果。取消及系统异常必须记录理由，不能用取消绕过正常收台流程。

4. 分阶段工作包

P0：需求、契约与试测基线

输入：主设计文档、现场桌面尺寸、仪器种类、候选相机和网络条件。

交付文件：contracts/session.schema.json、contracts/analysis.schema.json、contracts/openapi.yaml、docs/验收报告模板.md，以及文档中的需求追踪更新。

  • ☐ 明确学生登录方式、终端与台位绑定方式、课程清单来源和留存策略。身份方案仅收集必要标识，不将姓名写进文件名、日志或图像。
  • ☐ 冻结本计划定义的正式 lifecycle 和合法转换，禁止直接从登录状态跳到判定完成；结束请求重复发送必须返回原有收台步骤或已有结果，进入正常收台流程后不得返回 IN_PROGRESS。
  • ☐ 将业务状态、分析 attempt 状态和同步状态分别定义。会话本地完成与网络同步成功不互为前提；每次重拍创建新 attempt，保留前次失败原因和图像关联。
  • ☐ 给每个结果记录模型、算法、配置、相机标定和输入图像哈希；对模型、阈值更新采用新版本，历史记录保留当时版本。
  • ☐ 定义 needs_review 的可见文案：“本次无法可靠分析，请重拍或联系运维”，并保留机器可读原因码。
  • ☐ 冻结报告字段：会话伪名、实验名称、首末拍时间、仪器位置状态、bbox 说明、残余区域、分数/不可判定原因、版本和记录 ID。
  • ☐ 编制相机位置 A/B 试测表。至少比较高位近顶视与后上方斜视，记录覆盖、遮挡、高物体视差、触摸屏反光、日常碰撞和安装维护成本。

完成定义：每项需求都有唯一 ID、实现任务、验收证据；结果 Schema 能表达稳定、移位、缺失、新增、不可判定和残余变化；没有教师改分或改判 API。

P1：采集、坐标与 AnchorDiff 集成

依赖：P0；版本锁定的 AnchorDiff；一台普通开发主机和候选相机。先验证准确性再决定端侧采购规模。

交付文件：services/terminal/capture.py、alignment.py、analysis_adapter.py、tests/integration/test_geometry_contract.py、docs/相机安装与标定记录.md。

  • ☐ 采集稳定桌面重复图像，比较自动曝光与锁定曝光；在持续亮度变化时记录门控行为，避免把照明变化直接判为扰乱。
  • ☐ 把首次合格帧和结束选中帧分别固定下来，所有检测必须对应准确的帧 ID。多帧场景先选帧再检测，不对全部帧复用同一组框。
  • ☐ 将结束图像先对齐到基线图坐标，再在对齐图上检测，保证 AnchorDiff 输入检测框和图像同坐标。不要依赖尚未同步变换 final 检测框的路径。
  • ☐ 首拍冻结有效矩形 ROI，并以此裁剪首末分析输入。AnchorDiff v0.6.1 的现有分母是整个输入图，不能把任意 valid ROI mask 当作已支持能力；结束图无法完整覆盖冻结 ROI 时直接拒答。
  • ☐ 外部对齐在调用 core 前执行独立门控，并将几何证据与原因保存进 attempt。core 对预对齐输入产生的恒等对齐 confidence=1 不得覆盖或抬高外部对齐置信度，也不得解除此前失败状态。
  • ☐ 使用一组已知角点和人工框验收透视变换、ROI、letterbox 逆变换和 bbox/mask 尺寸。设置非方形输入测试，捕获宽高顺序错误。
  • ☐ 在对齐图上输出 overlay；如展示原始结束图，则显式对 bbox 和 mask 做逆变换。绝不在原图上直接叠加分析坐标 mask。
  • ☐ 测试默认容差 0.1 附近的合成位移，以及实际不同大小仪器的中心定位重复性；合成测试只验逻辑，不代替真实精度。
  • ☐ 记录稳定小位移的边缘残余现象，设计边缘带容忍策略的对照实验；不能简单清空整个稳定 bbox 内的变化，以免掩盖真实残留物。
  • ☐ 增加缺标记、手部/遮挡、强相机位移、检测异常为空等应用层门禁，说明哪些由可计算规则判断、哪些只能提示重拍。

完成定义：同一坐标系契约全部通过；标记失效不产生自信分数；基线冻结后不因重试而静默换图；能够输出可追溯的算法结果与 bbox/残余说明。未通过这些门禁不得进入真实仪器结果演示。

P2：先完成业务闭环

依赖：P0 API 和 P1 图像契约。允许使用已明确标记为人工标注输入的检测数据进行开发，以免业务进度依赖模型训练完成。

交付文件：apps/terminal-ui/、apps/teacher-web/、services/terminal/sessions.py、local_store.py、services/server/records.py、exports.py 和端到端测试。

  • ☐ 实现登录、实验选择、首拍倒计时、资料与清单、点击结束、收台步骤、终拍、结果解释与重拍路径。
  • ☐ 首拍质量未通过时不能进入正常实验状态；首拍已通过后持久化，不因应用重启自动重建。
  • ☐ 收台向导按本次基线显示仪器和提示，位置大体恢复即可；不得生成固定归位区要求。
  • ☐ 保存状态转移、采集事件和结果，使用事务把“分析完成”和本地记录写入一起提交。失败后保持可重试状态。
  • ☐ 后台只读查询详情、时间筛选、台位/课程筛选和报告导出；任何写分、改状态、替换原始证据的请求均由服务端拒绝。
  • ☐ 教师详情页同时显示扰乱度、每个对象 bbox 对应变化及残余区域。分数为空时显示原因，不能显示 0 或默认“整洁”；学生端只显示提交、重拍、不可判定和同步状态，不展示完整分数与逐框报告。
  • ☐ 首次终拍之外最多允许 3 次额外重拍，持续失败后以 INCOMPLETE 保存“不可判定”收台记录并提示运维处理，避免学生陷入循环；允许重拍的状态下，每次学生触发采集创建独立 attempt，不覆盖此前结果。
  • ☐ 将技术错误隐藏在学生正常流程之外，学生看到可行动提示；运维页和日志保留原因码、设备状态和记录 ID。

完成定义：使用人工检测输入可以从登录走完报告导出；重复结束不重复建会话；教师只读在后端执行；所有截图、日志和导出均通过去敏审查。

P3：数据集与仪器检测训练

依赖：P1 安装方案；数据规范。类别数由实际教学需要和可获得训练数据决定，新类别必须有数据及验收记录。

交付文件：vision/evaluation/、数据 manifest、标注规范、训练配置、模型卡、冻结测试报告；真实图像和权重存放在 Git 外受控位置。

  • ☐ 按台位、日期、采集场次和物理仪器实例建立分组清单。相邻帧、同一桌面布置及高度近似的首末图不能随机拆到训练和测试两侧。
  • ☐ 记录仪器类别、完整 bbox、遮挡程度和可见性。加入无目标图、相似物品、多台同类仪器及大幅光照差异，不把线缆硬编为仪器类别。
  • ☐ 先完成可复现的轻量检测基线，按真实数据比较 nano/small 模型的精度、漏检率、定位重复性和端侧时延；不从参数量直接宣称更适合。
  • ☐ 只用训练集调模型、验证集选超参数，冻结测试集一次性评估。任何查看测试错误后进行针对性修改，都必须记录并重新建立独立测试集。
  • ☐ 把同类仪器调换、明显离位、部分遮挡、仪器缺失、新增仪器和纯桌面残余变化作为独立系统样本，不只报告检测 mAP。
  • ☐ 验证高成本候选拒配、unmatched 处理和同类身份不确定性；仅同类别几何匹配不足以证明原仪器未被替换。
  • ☐ 记录模型许可证、训练框架版本、数据授权、训练 seed、split manifest 哈希和权重哈希。使用模型代码与权重前分别核对许可证。

完成定义：训练可重跑，测试分组可核查，指标按类别和场景报告；系统缺失误报、位置状态及质量拒答通过建议门槛或有明确降级方案。

P4：RK3588 部署与真实性能

依赖：P3 选定模型；P1 坐标契约；RK3588 候选板和与生产相同的供电、散热、相机。

交付文件：vision/detectors/、端侧依赖锁定、模型转换配置、tests/hardware/ 和硬件评测报告。

  • ☐ 导出 ONNX，针对实际模型原始输出实现解码、置信度计算、NMS 和 letterbox 逆变换。AnchorDiff 的默认六列输出解码不能直接视为任意 YOLO 头部解码。
  • ☐ 通过同一批图对照训练框架与 ONNX 的类别、坐标、分数和 NMS 结果。非方形输入、RGB/BGR、NCHW/NHWC 均单独验收。
  • ☐ 按实际 RKNN Toolkit/Runtime 版本转换并核对 Runtime API 类名和输入布局；禁止以桌面 ONNX 通过代替 RKNN 已兼容。
  • ☐ INT8 校准只使用训练或单独校准集，覆盖实际曝光和仪器尺度；与 FP32/FP16 比较关键指标下降，不使用冻结测试集做量化调参。
  • ☐ 测量单次采集到结果显示的总时延和各步骤耗时；同时记录 p50、p95、峰值内存、CPU/NPU 利用率、温度及频率。
  • ☐ 连续运行至少 8 小时进行热稳定试测，模拟高温季节条件并采用设备允许的范围；发生降频、USB 摄像头重连和内存增长时暂停采购扩展。

完成定义：真实硬件链路无坐标偏差，精度损失可接受，延迟和长时间稳定性有可复查记录。若 NPU 适配未通过，使用已验证的 CPU/ONNX 方案继续试点，并明确性能限制。

P5：恢复、只读权限、数据和部署

依赖：P2、P4；部署环境及身份源。

交付文件：services/terminal/sync.py、services/server/auth.py、retention.py、deploy/、故障恢复脚本和安全验收记录。

  • ☐ 每次状态转换持久化；进程在首拍后、收台中、终拍后和分析后退出，重启均恢复为对应会话与重试入口。
  • ☐ 使用本地 outbox 保存待同步记录，后台以唯一记录 ID 和幂等键去重。网络恢复后提交次数可以大于一，但最终只能存在一份相同版本结果。
  • ☐ 采用有上限的指数退避和随机抖动，服务端限流时遵循重试提示；认证失效、Schema 不兼容与数据哈希冲突停止自动重试并告警。
  • ☐ 图像上传与结果同步使用 manifest 标记完成情况，图片缺失时后台不能显示“证据完整”；传输中断续传后核对哈希。
  • ☐ 服务端逐请求验证学生、教师、管理员权限。教师只能读取授权课程/台位记录；管理员可以更新未来配置，但不能覆盖已生成结果。
  • ☐ 身份数据与图像/分析结果分离存储，文件名使用不含学号姓名的随机 ID；日志不记录令牌、登录凭据或完整学生标识。
  • ☐ 内网部署使用身份认证和 TLS，终端只配置必要的后台地址；不暴露未认证摄像头流、调试接口和任意文件读取接口。
  • ☐ CSV 导出对以 = + - @ 及控制字符开头的文本执行安全文本输出，避免电子表格公式执行；PDF/HTML 报告转义输入，避免注入。
  • ☐ 配置允许的数据保留期和清理任务，备份也执行对应周期；先确认未同步证据和未完成会话不会被清理，再启用自动删除。
  • ☐ 在独立恢复环境演练数据库和图片恢复，核对哈希与关联关系，不以“有备份文件”视为恢复验证通过。
  • ☐ 发布包含前后版本、迁移说明、回滚条件和模型哈希。数据库迁移采用向后兼容方案，旧终端不同步不兼容记录。

完成定义：故障恢复矩阵全部通过；教师无写入路径；去敏、导出、备份与恢复实测；发布记录能够重建某次分析使用的环境。

P6：现场试点和扩大部署

  • ☐ 在教学中采集独立场次，包含不同台位、照明、仪器组合和学生收台行为。任何人工参考结论只用于离线验收，不写回系统运行结果。
  • ☐ 每天复查不可判定原因、重复重拍、位置误报、缺失误报和报告可理解性，优先修复高影响错误。
  • ☐ 报告总体指标及各场景分层指标，不能用平均值掩盖斜视大仪器、同类仪器和弱光场景的失败。
  • ☐ 形成缺陷清单、改动版本和再验证数据。只在 P1、P4、P5 和试点门槛均通过后追加硬件采购与台位。

完成定义：有真实场景验收报告及版本锁定；所有高影响缺陷完成修复或明确限制；采购规格依据实测证据冻结。

6.2 验收数据构成

  1. 坐标契约数据：带已知变换的图像、非方形输入、不同 bbox 尺寸、对应 mask，以及至少一个非恒等单应性。用于排查几何错误，不计为现场精度。
  2. 检测冻结集：按采集场次、台位和物理仪器实例分组；主要类别建议先获得至少 100 个独立可见实例，再根据区间宽度追加。100 个实例不代表已经充分覆盖教学场景。
  3. 状态成对集：建议至少 200 组独立首末拍，覆盖稳定、小幅移动、明显移动、缺失、新增、同类替换、纯残余变化和多目标。相邻帧不作为独立样本扩大数量。
  4. 阈值边界集：对每种代表性目标采集位移位于 0.08–0.12 的样本，同时覆盖不同框尺寸；记录人工中心标注误差，不能把标签噪声归因于算法误报。
  5. 质量与安装集：遮挡、无标记/部分标记、相机碰动、反光、过曝、弱光、桌面外变化、高仪器视差和无目标场景。
  6. 系统故障集：断电模拟、进程异常退出、断网、后台超时、磁盘不足、图片损坏、模型缺失、配置不兼容和时钟偏差。

比率同时报告分子、分母和 Wilson 95% 置信区间。对于零次缺失误报，使用单侧 95% 二项上界时，约 100 个独立样本可将上界压到约 3%，约 300 个可压到约 1%；这只是样本量规划依据，不替代实际分层评估。台位/场次内样本相关时应按场次统计或分组 bootstrap，不能当作完全独立。

扰乱度使用预先定义的成对排序或人工区域标注验证；多位参考标注者先记录一致性。报告拒答率、非拒答结果的错误率及二者关系，明确系统牺牲多少覆盖率换取可靠性。
